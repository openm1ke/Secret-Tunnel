# Проверка серверного агента — 9 ноября 2026

Следующий шаг после [стабилизации](STABILIZATION-2026-11-09.md): закрыть диагностическую часть A7 из [аудита](AUDIT-2026-11-09.md).

## Поведение клиента

Встроенный движок после проверки host key и входа по ключу запрашивает возможности агента, затем проверяет настоящий handshake STMUX003. На desktop это также кнопка «Проверить SSH и агент» в настройках сервера. Она использует выбранный SSH-движок; System OpenSSH по-прежнему проверяет обычный SSH-доступ и не требует нашего агента. На Android отдельная кнопка находится в настройках сервера рядом с проверкой отпечатка; приватный ключ расшифровывается только во временный файл со своим уникальным именем и удаляется владельцем операции.

Проверка не включает VPN/перехват, не устанавливает программы и не меняет службы сервера. При обычном подключении маршруты активируются только после успешной проверки. При запуске туннеля запрос выполняется на его же SSH-соединении; отдельная кнопка запускает самостоятельную диагностическую SSH-сессию. Короткий диагностический exec-канал завершается **до** открытия единственного канала данных; на каждый запрос статуса проверка не повторяется.

Новые команды агента:

```sh
~/.local/bin/secret-tunnel-agent --version
~/.local/bin/secret-tunnel-agent --capabilities
```

`--capabilities` возвращает один JSON-объект и завершается без ожидания stdin:

```json
{"schema":1,"agent_version":"0.3.0","os":"linux","arch":"x86_64","protocols":[3],"tcp":true,"udp":true,"max_flows":2048}
```

`max_flows` зависит от доступных файловых дескрипторов. Фактический лимит сессии согласовывается в handshake. Агент обслуживает TCP и UDP только через STMUX003. Общий stdout+stderr ограничен 8192 байтами. На открытие канала диагностики и ответ выделено по 4 секунды, на handshake данных — 10 секунд. Общий deadline запуска составляет 45 секунд. Stop отменяет ожидание.

## Совместимость и ошибки

Для клиента 0.3.0 требуется агент с `--capabilities` schema 1 и поддержкой STMUX003 TCP/UDP. Клиент отклоняет старый агент до открытия канала данных. STUDP001 и STUDP002 удалены из агента.

| Код | Что произошло / следующее действие |
| --- | --- |
| `AGENT_MISSING` | SSH/ключ уже приняты; установить агент в `~/.local/bin/secret-tunnel-agent`. |
| `AGENT_NOT_EXECUTABLE` | Проверить права, архитектуру бинарника и его системные библиотеки. |
| `AGENT_INCOMPATIBLE` | Установить текущий агент со schema 1 и STMUX003 TCP/UDP. |
| `AGENT_RESOURCE_LIMIT` | Серверу не хватает файловых дескрипторов для минимального лимита. |
| `AGENT_INVALID_RESPONSE` | Проверить версию агента и лишний вывод shell startup-файлов. |
| `AGENT_CHECK_FAILED` | Команда не завершилась корректно или сервер запретил exec. |
| `AGENT_CHECK_TIMEOUT` / `AGENT_START_TIMEOUT` / `AGENT_START_FAILED` | Ограниченное ожидание/разрыв соединения; сетевой сбой допускает повторную попытку. |

Фиксированный shell wrapper использует exit 200 для отсутствующего файла и 201 для отсутствия execute permission. Обычные 126/127 от запуска существующего файла означают ошибку запуска/loader, а не отсутствие установленного файла. SSH/auth/host-key ошибки возникают раньше и не маскируются сообщением про агент. Ошибки установки/совместимости останавливают авто-reconnect до действия пользователя. На Android таймаут агента сохраняет сообщение «SSH и ключ проверены», вместо ошибочного совета проверять доступность SSH-сервера.

## Проверки и границы

Регрессии используют локальный SSH с одноразовыми ключами и лимитом одного открытого session channel. Проверяются обмен TCP/UDP после диагностики, отказ старому агенту, отсутствие файла, права, размер и формат ответа, таймаут, отказ авторизации и изменённый pin. Stop во время зависшего preflight освобождает SOCKS-порт. CLI-тест проверяет ответ `--capabilities` при открытом stdin.

Проверка на Windows и реальном телефоне описана в [отчёте замеров 0.3.0](PERFORMANCE-0.3.0.md).

Дополнительно desktop crate теперь выпускает только `rlib`: EXE/APP используют Rust linking, отдельные `staticlib`/`cdylib` не нужны. До изменения только один debug staticlib занимал около 965 MiB, а повторная линковка тестов на заполненном диске завершилась LNK1318. Штатный `cargo clean --package secret-tunnel --profile dev` очистил результаты этого пакета; зависимости и исходники сохранены. Android JNI остаётся отдельным `cdylib` в `android/native`.

## Далее

Серверный установщик проверяет SHA256, архитектуру и обмен TCP/UDP во временном бинарнике. Затем он сохраняет предыдущую версию и атомарно заменяет файл в `~/.local/bin`. Команда `--rollback` проверяет SHA256 резервной копии и восстанавливает её. Установка из интерфейса и длительные испытания остаются в [плане](ROADMAP-2026-11-09.md).
