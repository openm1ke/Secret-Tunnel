# Secret Tunnel для Android

Android-клиент находится в **этом же репозитории**, в `android/`. Это нативный Kotlin-интерфейс и `VpnService`, а не запуск Windows EXE/драйвера на телефоне. `tunnel-core` компилирует тот же Rust SSH/SOCKS/UDP-код, что использует Windows-клиент; копии сетевого протокола нет. Общие исходники пока физически находятся в `src-tauri/src/`, а общая crate подключает их через `#[path]`.

## Возможности первой версии

- SSH по приватному ключу; локальный SOCKS5 CONNECT и UDP ASSOCIATE.
- Выбор установленных приложений галочками, поиск по названию/package name. Показываются видимые приложения с launcher activity и разрешением INTERNET текущего Android-профиля; это не список всех системных служб.
- TCP и UDP выбранных приложений → локальный TUN → hev-socks5-tunnel → наш Rust SOCKS → SSH. Непосредственно с телефоном зарубежный сервер обменивается данными через SSH; UDP-agent работает в SSH exec-канале, отдельный UDP-порт на сервере не нужен.
- IPv4/IPv6, DNS выбранных приложений также через туннель (DNS-сервер по умолчанию 1.1.1.1).
- Фоновый foreground service с постоянным уведомлением и кнопкой остановки.
- Переподключение после сбоя SSH с задержкой до 15 секунд. Уже созданный TUN при переподключении сохраняется: выбранный трафик не переключается намеренно в DIRECT. После ручной остановки обычная маршрутизация восстанавливается. Завершение процесса системой и перезагрузка телефона не покрываются always-on/lockdown: always-on сейчас отключён в манифесте.
- Счётчики полезных TCP/UDP-данных и график; данные суммируются при переподключениях одного VPN-сеанса. Журнал последних ошибок Rust-клиента.
- Приватный ключ хранится зашифрованным AES-GCM с ключом Android Keystore. Короткоживущий файл MODE_PRIVATE нужен только для загрузки ключа Rust-библиотекой и удаляется после попытки подключения. Резервное копирование приложения отключено. Ключи с passphrase пока не поддерживаются.
- Проверка SHA256-отпечатка SSH-сервера. Первый неизвестный ключ **отклоняется**: приложение показывает отпечаток для проверки и сохранения пользователем. Изменение ключа при уже сохранённом отпечатке не принимается автоматически.

Текущая Android-версия ориентирована на выбор приложений. Редактор доменных regex/DIRECT-исключений из Windows, несколько серверных профилей, запуск после перезагрузки и автоустановка UDP-agent на сервер в Android UI пока не перенесены. На сервере должен быть ранее установленный совместимый `~/.local/bin/secret-tunnel-agent`.

## Установка и подключение

1. Установите `artifacts/android/SecretTunnel-debug.apk`. Это локальная debug-сборка для проверки, не магазинный релиз.
2. Укажите SSH-сервер, порт и пользователя. Импортируйте **свой** приватный SSH-ключ через системный выбор файла. Никаких ключей/паролей конкретного сервера в APK нет.
3. На вкладке «Приложения» отметьте Discord, Telegram, Firefox или другие нужные приложения.
4. Нажмите «Подключить». Клиент сам получит ключ сервера; сверьте показанный отпечаток по доверенному каналу и подтвердите доверие. Подключение продолжится автоматически, затем Android попросит разрешение VPN. Отпечаток вручную не вводится.
5. Переподключите тестовое приложение. Проверьте HTTPS, DNS, голос/видео и рост счётчиков. После изменения списка приложений перезапустите VPN-сеанс.

Для сверки отпечатка на сервере: `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`. Проверяйте именно тот тип host key, который предложил сервер. Android обычно допускает один активный VPN на профиль; другой VPN потребуется остановить.

Для отдельного ключа телефона нажмите «Создать отдельный ключ этого телефона»: клиент войдёт уже разрешённым импортированным ключом, добавит Ed25519-ключ в authorized_keys вашего пользователя и проверит новый вход перед сохранением. Другие ключи и службы сервера сохраняются. Подробности: [подключение и доверие](android-connection.md).

## Сборка

Требуются macOS, Linux или WSL, JDK 17, Android SDK platform 34/build-tools 34.0.0, NDK 27.0.12077973, Rust stable, Git, Python 3, make. Скрипт автоматически выбирает macOS/Linux host toolchain NDK. Эмулятор не нужен для сборки APK.

```bash
export JAVA_HOME=/path/to/jdk17
export ANDROID_HOME=/path/to/android-sdk
export PATH="$HOME/.cargo/bin:$JAVA_HOME/bin:$PATH"
bash scripts/build-android.sh
```

На текущем Windows-компьютере исходный SDK расположен в `D:\SDK\AndroidSDK`, Linux JDK — в `D:\SDK\LinuxSDK\amazon-corretto-17.0.12.7.1-linux-x64`. Для сборки подготовлен изолированный SDK view в `D:\SecretTunnelBuild\android-sdk-view`: он использует чистую platform 34 в кэше WSL, необходимые build-tools и NDK, без перебора старых SDK/эмуляторов. Windows-скрипт выбирает этот view, если он существует:

```powershell
./scripts/build-android.ps1
```

Пути переопределяются параметрами `-SdkDirectory` и `-JavaDirectory`. Это **Linux SDK/JDK**, используемые через WSL. Скрипт не скачивает эмулятор и не меняет защиту Windows. Если принадлежащие текущему пользователю NDK/JDK на `/mnt/...` имеют непригодные NTFS/Unix права после переноса, скрипт восстанавливает владельцу доступ к этим каталогам инструментов. Rust для WSL устанавливается отдельно; Android Rust targets добавляются скриптом.

Сборка создаёт ARM64 и x86_64 `.so` с выравниванием ELF-сегментов 16 KiB, собирает APK, запускает lint и доступные Gradle unit tests. Выход: `artifacts/android/SecretTunnel-debug.apk`. Для установки через adb: `adb install -r artifacts/android/SecretTunnel-debug.apk`.

Кэш по умолчанию: `$HOME/.cache/secret-tunnel-android`; его можно перенести через `ANDROID_BUILD_ROOT`. На текущей машине тяжёлые подкаталоги `rust-target`, `gradle-home`, `ndk-obj` перенесены в `D:\SecretTunnelBuild\android-cache`, а исходные пути сохранены символическими ссылками. `GRADLE_USER_HOME`, `ANDROID_NDK_HOME`, `HEV_SOURCE_DIRECTORY` и `GRADLE_CMD` также переопределяются. Gradle wrapper закреплён на 8.7 и проверяет SHA256 дистрибутива; подготовленная локальная установка Gradle может использоваться из кэша или через `GRADLE_CMD`.

Нативный tun2socks закреплён на `heiher/hev-socks5-tunnel@8e3b4cd7168fe64b64f8b58537b5623fb6a7074d`; вложенные репозитории проверяются по gitlink. Исходники скачиваются в кэш, сторонние уведомления об авторских правах включаются в APK assets. В YAML используется `socks5.udp: udp`: UDP идёт локально в наш SOCKS, где уже оборачивается в собственный SSH-протокол. Проприетарный hev UDP-over-TCP режим не используется.

Workflow `.github/workflows/android.yml` собирает debug APK для pull request/push затронутых файлов или вручную. Публикации в Google Play и release-ключа подписи в нём нет.

## Проверки

Общий Rust-код: `cargo test --manifest-path tunnel-core/Cargo.toml --locked` (включая отказ при пустом/неверном SSH fingerprint). Проверка JNI на хосте: `cargo check --manifest-path android/native/Cargo.toml --locked`. Windows регрессия: существующие unit tests `src-tauri`.

Пример `tunnel-core/examples/check_tunnel.rs` запускает отдельный SOCKS на 1082 по переданным аргументам и завершает его через 45 секунд. Его можно проверить `python scripts/check_socks_udp.py 1082`: HTTPS, восемь UDP DNS-запросов и закрытие UDP-ассоциации. Этот тест проверяет общий транспорт, **не Android VPN API**.

Успешная сборка APK не заменяет проверку на телефоне: отдельно нужны системное VPN-согласие, фактический выбор приложений, IPv6/DNS, смена Wi-Fi/мобильной сети, блокировка экрана, отзыв разрешения и голос/видео Discord. Результаты локальной сборки и доступных проверок записываются в `ANDROID-BUILD-2026-11-08.md`.

На macOS APK собран и **реально проверен на отдельном Android 17 ARM64-эмуляторе с 16-КБ страницами**: выбранный UID → VPN/TUN → SOCKS → SSH → HTTPS/UDP DNS; другой UID без VPN; очистка после остановки. Подробности, ограничения и повторение: [Android emulator validation](ANDROID-EMULATOR-2026-11-08.md).
