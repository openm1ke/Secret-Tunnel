# Перехват приложений Windows без TUN

## Выбранный компонент

Адаптер использует ProxyBridge 4.3.0 (MIT), revision `cb897b017a88a142ec803c3af138b0ad75c2ae12`. Его движок перенаправляет TCP/UDP через подписанный WinDivert 2.2.2, работающий на WFP. Виртуальный сетевой адаптер и отдельный UDP-транспорт до зарубежного сервера не нужны.

Схема: Discord → WFP/WinDivert → ProxyBridge → локальный SOCKS5 Embedded Rust SSH → существующая SSH-сессия → серверный UDP-агент / TCP direct-tcpip.

Это адаптер к готовому WFP-based движку, а не собственный callout-драйвер. Интерфейсы ядра, подпись и поддержка драйвера остаются у upstream-проекта.

## Что реализовано

- Вкладка «Приложения», список имён exe, путь к локальному компоненту, состояние и команды запуска/остановки.
- По умолчанию выбран Discord.exe. Разрешены точные имена и полные локальные Windows-пути без масок; нельзя включить ssh.exe, движок и собственный клиент. Кнопка поиска Discord добавляет также точные пути Update.exe из установленных Discord/Canary/PTB; общее правило Update.exe не создаётся.
- Профиль .pbprofile создаётся вне репозитория в каталоге конфигурации пользователя. Сначала DIRECT для транспорта, затем TCP+UDP PROXY выбранных приложений, затем DIRECT для остальных.
- Перехват требует работающий embedded-туннель на loopback, комплект движка и права администратора. Автозапуска перехвата нет.
- stdout/stderr движка читаются в Runtime logs, при маскировании адреса соединений скрываются.
- Остановка туннеля, сброс конфигурации и закрытие окна останавливают дочерний процесс перехвата.
- Команды с сетевым ожиданием вынесены из main-thread dispatch Tauri.

При выключении перехвата новые соединения идут напрямую. Это MVP без независимого kill switch: аварийное завершение движка также не гарантирует блокировку выбранных приложений. Уже существующие соединения могут продолжаться по старому маршруту — Discord нужно полностью перезапустить после изменения режима. DNS системной службы Windows не всегда принадлежит Discord.exe; отдельная политика DNS ещё не реализована.

## Комплект

В одном каталоге ожидаются:

```text
ProxyBridge_CLI.exe
ProxyBridgeCore.dll
WinDivert.dll
WinDivert64.sys
LICENSE.ProxyBridge.txt
source-revision.txt
лицензии WinDivert и его зависимостей
```

Путь по умолчанию: `%APPDATA%\secret-tunnel\tools\proxybridge\ProxyBridge_CLI.exe`. Наличие файлов проверяется отдельно от успешной загрузки драйвера. Приложение не устанавливает сторонние службы, не меняет firewall/маршруты и не отключает защиту Windows. Сам WinDivert при разрешённой загрузке регистрирует свой драйвер; это требует администратора.

Для сборки userspace CLI из проверенного исходного репозитория:

```powershell
./scripts/build-redirect-cli.ps1 -SourceDirectory D:/path/to/ProxyBridge -OutputDirectory D:/path/to/component
```

Скрипт проверяет revision, компилирует только CLI и сохраняет MIT-лицензию. Локальная модификация: после сообщения готовности stdout сбрасывается; байт в stdin вызывает Stop; EOF при завершении родителя тоже вызывает Stop. Исходный upstream-каталог не изменяется. Адаптер требует маркер сборки source-revision.txt с этой модификацией; немодифицированный CLI не является поддерживаемым комплектом. Если штатная остановка зависла, через пять секунд завершается только собственный дочерний процесс.

## Первоначальная блокировка на тестовой машине

7 ноября 2026 защита Windows заблокировала чтение/распаковку официального архива `WinDivert-2.2.2-A.zip` с сообщением о вирусе или потенциально нежелательной программе. Драйвер не извлечён, подпись фактического файла не проверена, загрузка не выполнялась. Обход блокировки, добавление исключений и изменение защиты не выполнялись.

CLI отдельно собран из исходников и `--version` подтвердил 4.3.0; он не содержит драйвер и не обеспечивает перехват самостоятельно. На этом этапе реальный перехват был заблокирован до получения проверенного комплекта, разрешённого системой. Нельзя считать функцию готовой к использованию на основании успешной сборки GUI.

## Проверки

### Цепочка запуска Discord

На тестовой машине найден `%LOCALAPPDATA%\Discord\Update.exe`. SquirrelSetup.log подтверждает запуск Discord.exe этим обновлятором. Наблюдаемые основной процесс, renderer, crashpad, GPU и utility `network.mojom.NetworkService` используют Discord.exe, поэтому правило по имени покрывает все их экземпляры независимо от PID и версии каталога app-*.

Добавлена поддержка точного пути обновлятора и кнопка «Добавить Discord и обновлятор». Такое правило охватывает проверку обновлений, не захватывая все процессы с распространённым именем Update.exe. Голосовой UDP нужно отдельно подтвердить во время звонка; по одной структуре процессов это не доказано.

### Проверка после ручной распаковки пользователем

Пользователь предоставил распакованный официальный комплект в `D:\SecretTunnelChecks\WinDivert-2.2.2-A`. Authenticode для x64 WinDivert64.sys: Valid. SHA256: `8DA085332782708D8767BCACE5327A6EC7283C17CFB85E40B03CD2323A90DDC2`.

Собраны адаптированный CLI и ProxyBridgeCore.dll; комплект установлен в пользовательский каталог Secret Tunnel. Добавлен `scripts/build-redirect-core.ps1`: он проверяет подпись драйвера, собирает userspace-компоненты из закреплённого revision и копирует файлы, не загружая драйвер самостоятельно.

В отдельном тесте с подтверждённым UAC драйвер загружен. Правило PROXY действовало только для двух тестовых exe, остальные приложения DIRECT:

- STTcpProbe.exe (копия системного curl), без параметров прокси: внешний IP совпал с ответом через эталонный SSH SOCKS.
- STUdpProbe.exe: обычный UDP DNS-запрос получил корректный ответ; строка движка подтвердила Proxy SOCKS5 (UDP) для этого процесса.
- CLI подтвердил штатный Stop и завершился; после теста процесс перехвата не остался запущенным.
- GUI-клиент оставлен работающим с embedded SOCKS 1080, HTTPS HTTP 200. Настройки приложений восстановлены/сохранены для Discord.exe; тестовые имена не добавлялись в пользовательскую конфигурацию.

Во время проверки защита в реальном времени была отключена пользователем. Работоспособность комплекта при включённой защите пока не подтверждена. Подпись файла не заменяет антивирусную проверку. Настоящий Discord (чат/голос) пока не тестировался; на момент теста процесс Discord не был запущен.

- Unit: ограничение правил выбранными exe, BOTH TCP/UDP, порядок bypass/default-direct, отказ масок, путей и рекурсивного перехвата.
- Frontend production build и тесты транспорта/relay проходят.
- Следующий интеграционный тест после разрешённой установки драйвера: отдельное тестовое приложение TCP/UDP, отсутствие TUN и дополнительных внешних соединений, затем Discord chat/voice, перезапуск процесса, остановка перехвата, обрыв SSH и очистка дочернего процесса.
