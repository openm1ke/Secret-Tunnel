## Находки

### A1 · P1 · Отменённый TCP relay продолжает удерживать сокет

**Код:** `stream-mux/src/relay.rs:22`, `:33`, `:40`; удаление admission state — `stream-mux/src/lib.rs:991` и `:256`.

`relay` ждёт одновременно upload/download через `try_join!`. Чтение/запись локального сокета не обёрнуты в наблюдение отмены потока. Если `write_all` заблокирован, полученный Abort удаляет поток из карты и обнуляет active, но не прерывает этот write. Вторая половина relay также может ждать чтения. Сокет, task и удерживаемый Received остаются живы до внешнего события/остановки транспорта.

**Воспроизведение:** реальный Endpoint + relay; локальный duplex с буфером 1 байт; отправка 16384 байт без чтения получателем; отмена потока. Сервер уже сообщает `active=0`, но relay не завершается за 500 мс. Сам тест не подключает интернет и не заменяет relay моками.

**Последствие:** многократные отмены при зависающих получателях могут накапливать задачи, дескрипторы и буферы вне лимита active flows. Заявленный бюджет ограничивает карту/очереди, но не все фактически живые ресурсы.

**Исправление:** общий cancellation token/state в каждой половине relay; отменяемые read/write/shutdown и bounded teardown. Разделить «получен Abort» и «ресурсы потока освобождены», не освобождать admission раньше завершения owner-задачи. Проверить реальные TCP, обе стороны, half-close и тысячи циклов cancel/reopen.

### A2 · P2 · Поздний подписчик теряет уведомление о закрытии

**Код:** `stream-mux/src/lib.rs:531`, `:533`, `:689`.

`State::cancel` вызывает `watch::Sender::send(true)`, игнорируя ошибку. При отсутствии receivers Tokio не сохраняет новое значение. `Sender::is_closed()` смотрит atomic cancelled и возвращает true; поздний `Sender::closed()` подписывается на watch, видит false и может ждать бесконечно. Дополнительный тест воспроизводит именно это противоречие.

**Исправление:** сохранять терминальное состояние независимо от наличия подписчиков (`send_replace`/устойчивый cancellation token); согласовать `is_closed`, `closed`, `recv`, `open` и shutdown. Добавление `select` для A1 без исправления A2 недостаточно надёжно. Проверить аналогичное уведомление `Inner::fail`, где тоже используется send.

### A3 · P1 · Desktop reconnect зависит от UI и не отменяется кнопкой Stop

**Код:** `src-tauri/src/lib.rs:1298`, `:1321`, `:1331`, `:1332`.

При обнаружении падения `tunnel_status` очищает runtime, останавливает перехват, спит reconnect_delay и выполняет одну попытку start. Если она не удалась, следующий status видит пустой runtime и больше не пытается подключиться. Если во время sleep пришёл Stop, он видит пустой runtime, однако отложенный status затем всё равно может запустить туннель. Параметры берутся из выбранных на тот момент профилей. Перехват после успешного reconnect сам не восстанавливается — пользователь должен включить его заново.

**Доказательство:** анализ управляющего пути, без аварийного теста работающего Windows-клиента. Эти ограничения уже были отмечены прошлым аудитом и всё ещё присутствуют.

**Исправление:** фоновый supervisor, desired state + generation/session ID; отменяемый backoff с jitter; неизменяемый снимок профиля; отдельная политика восстановления interception. Status должен только читать снимок. Тесты: Stop во время backoff, повторные неудачи, закрытие окна, смена профиля во время ожидания.

### A4 · P1 · Android не восстанавливает умерший tun2socks

**Код:** `android/app/src/main/java/dev/secrettunnel/android/TunnelVpnService.kt:44`, `:54`, `:56`.

Когда `TProxyIsRunning()` false, монитор выбрасывает исключение, записывает ошибку и назначает новый опрос. Следующий опрос повторяет тот же путь: перезапуска обработчика или полного VPN-сеанса нет. SSH при этом может оставаться живым, а выбранный трафик не работает до ручного Stop/Start.

**Доказательство:** анализ ветвлений, инъекция падения native engine на устройстве в этой сессии не проводилась.

**Исправление:** единый автомат состояний SSH/TUN/engine, отдельные health checks, контролируемое восстановление с ограничением повторов. Тестировать forced engine exit, ошибку establish, исчезновение SSH и отмену восстановления пользователем.

### A5 · P2 · Настройки desktop могут быть повреждены или потеряны

**Код:** `src-tauri/src/lib.rs:444`, `:456`, `:463`; read-modify-write команды от `:862`.

Сохранение выполняется прямым `fs::write` без atomic replace/резервной копии. Прерывание записи может оставить неполный JSON; две конкурирующие команды могут перезаписать изменения друг друга. Также ошибка чтения config в `tunnel_status` происходит до проверки runtime и мешает обычному мониторингу.

**Исправление:** один владелец config/revision, сериализация изменений, temp + sync + atomic replace с корректной реализацией Windows; backup и проверяемое восстановление. Критерий — ни одна fault injection не уничтожает последнюю валидную версию.

### A6 · P2 · Телеметрия задерживает управляющие команды

**Код:** `src-tauri/src/lib.rs:625`, `:679`, `:804`, `:1303`.

`tunnel_status` удерживает runtime mutex во время измерения TCP latency и построения статуса; IPinfo использует отдельный процесс curl с timeout до 6 секунд. Это может задерживать Stop/Start. Измеряемая latency — отдельное TCP-подключение к SSH endpoint, не end-to-end задержка доставки UDP через мультиплексор. Runtime sampler работает по запросам статуса; в Android сервисная история уже реализована лучше.

**Исправление:** независимые sampler и IP lookup, краткоживущие locks, status из памяти, RTT/jitter/loss отдельного probe через туннель с точными подписями метрик.

### A7 · P2 · Обновление embedded-клиента требует ручного обновления агента даже для TCP

**Код:** `src-tauri/src/embedded_ssh.rs:404`, `:407`; `udp-agent/src/main.rs:6`.

В v3 весь TCP/UDP зависит от `--stdio-v3`. Без нового агента новый embedded-клиент не запустит даже обычный TCP, хотя прежний TCP шёл через SSH direct-tcpip. Это документированное изменение протокола, не ошибка формата; обратная совместимость есть со стороны нового агента для старых клиентов, а не наоборот.

**Улучшение:** preflight возможностей до активации маршрутов, понятные отдельные ошибки «SSH доступен / ключ принят / агент отсутствует или старый». Мастер установки только в пользовательский каталог: pin SHA256, проверка архитектуры, временный бинарник, self-test, atomic swap, backup/rollback. Существующие службы и authorized_keys не переписывать. Возможный TCP-only compatibility mode явно обозначать и блокировать неподдерживаемый UDP; не вводить скрытый DIRECT fallback.

### A8 · P2 · Android-операции доступа привязаны к Activity

**Код:** `android/app/src/main/java/dev/secrettunnel/android/MainActivity.kt:82`, `:335`, `:356`, `:375`.

Проверка сервера, импорт и регистрация ключа выполняются голыми Thread. При пересоздании Activity состояние операции не переносится; новый onCreate удаляет временные ключевые файлы, которые может ещё использовать старый worker. Это риск прерывания регистрации/неясного результата, особенно при повороте/выгрузке UI. На сервере уже мог появиться публичный ключ, хотя клиент его не сохранил.

**Исправление:** lifecycle-independent repository/ViewModel с идентификаторами операции и профиля; атомарная замена секрета после parse/auth; отдельные временные имена и удаление только владельцем. Тесты rotation/background/process recreation во время каждой стадии. Риск подтверждён кодом, не новым тестом вращения устройства.

### A9 · P2 · Секрет IPinfo и защита webview

**Код:** `src-tauri/src/lib.rs:685`, `:463`; `src-tauri/tauri.conf.json:23`.

IPinfo token сохраняется в JSON и попадает в URL аргумента curl. Hide-sensitive не защищает config и process argv. Одновременно CSP webview отключена. Это отдельные поверхности усиления защиты; эксплуатация XSS или кража токена этим аудитом не демонстрировались.

**Исправление:** OS secret store, HTTP-клиент без token в argv, редактирование диагностического экспорта; production CSP и минимальные Tauri capabilities. Ключи/профили и командные строки пользователя при аудите не выводились.

### A10 · P2 · Новые Android/macOS сценарии не являются обязательными CI-проверками

**Код:** `.github/workflows/android.yml:26`, `.github/workflows/ci.yml`, `.github/workflows/release.yml`.

Gradle build/unit/lint выполняются, но `NavigationTest`, `ProfileTest`, `VpnFixtureTest` и настоящий selected/unselected traffic не запускаются на эмуляторе в workflow. Desktop UI-скрипты тоже не включены в обычный CI. Тесты ложатся в репозиторий, но не защищают каждый PR от соответствующих регрессий. Успешные synthetic/stress отчёты предыдущей сессии этого не заменяют.

**Исправление:** обязательный быстрый набор unit/UI/parser; отдельный детерминированный эмуляторный smoke с локальным SSH fixture и агентом, без пользовательских секретов; stress/soak и аппаратные платформенные тесты по расписанию/перед релизом. Подключить RustSec/cargo-deny, fmt/clippy и проверку лицензий/фиксированных зависимостей.

## Ограничения и продуктовые решения, которые нельзя называть исправленными

- **Нет независимого fail-closed режима.** На desktop остановка/авария и очистка interception возвращают обычный DIRECT; Android отключает always-on support в manifest. Во время Android reconnect TUN сохраняется, но это не гарантия защиты после смерти процесса/перезагрузки. Нужны отдельные режимы «при ошибке блокировать» и «разрешать напрямую», с явным выбором пользователя и системной реализацией. Это известное ограничение, не скрытый обход существующего kill switch.
- **macOS DNS:** `macos_redirect.rs:128` ставит dnsEnabled=false. Выбор процесса сам по себе не гарантирует, что системные DNS-запросы идут через SSH. Domain regex доступен только Windows. Fake-IP TLS SNI — ограниченный workaround; не решает HTTP, ECH/скрытый SNI, DNS/QUIC целиком. Не применять непредсказуемый DIRECT fallback.
- **IPv6 на Android:** проверяется при старте; reconnect сохраняет прежний TUN/YAML. Если серверный выход IPv6 поменялся, маршруты не перестраиваются. Нужен тест изменения capabilities и явная политика пересоздания TUN. Не объявляю IPv6 bypass без пакетного доказательства.
- **`setMetered(false)` не ошибка:** согласно Android API VPN наследует meteredness underlying network. Утверждать, что приложение обязательно считает мобильную сеть безлимитной, было бы неверно: [VpnService.Builder](https://developer.android.com/reference/android/net/VpnService.Builder#setMetered(boolean)).
- **Один SSH TCP-транспорт:** v3 убирает лимит множества SSH exec-каналов и ограничивает очереди, но потери внешнего TCP по-прежнему задерживают все внутренние потоки. Следующий шаг — fairness, bounded media queues и измерения jitter/p95/p99. Устранить TCP head-of-line blocking, оставив единственный SSH/TCP транспорт, нельзя. SSH имеет собственный channel flow control: [RFC 4254, §5.2](https://www.rfc-editor.org/rfc/rfc4254.html#section-5.2).
- **Подпись macOS:** `tauri.macos.release.conf.json:12` использует ad-hoc signing (`-`), Apple notarization отсутствует; компонент перехвата устанавливается отдельно. Universal packaging не равно полной проверке перехвата на Intel Mac.
- **Низкая RAM/плохая сеть:** большие лимиты по totalMem — верхняя граница, не обещание при memory pressure. Нужны длительный Android background/Doze, реальный телефон, Wi-Fi↔LTE, loss/reordering и изменение MTU. Лимит STMUX receive-window не включает все стеки задач, kernel buffers и C/lwIP.
