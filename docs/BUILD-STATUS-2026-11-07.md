- Исходная установка Build Tools не прошла из-за места на C:. Повторная установка с путями D:\BuildTools, D:\VSCache, D:\VSShared завершилась успешно. Удалён только установленный в этой сессии необязательный компонент rust-docs; компилятор сохранён.
- Android-комплект перенесён из %USERPROFILE%\AppData\Local\CodexAndroid в D:\CodexAndroid. На старом пути junction; adb version и emulator -version успешно работают через него. Образы и настройки сохранены. До работ на C: было около 1,1 ГБ свободно, после переноса около 9,6 ГБ. Данные остальных программ не удалялись.
- Попытка очистки npm/Gradle cache отклонена автоматической проверкой безопасности, удаление не выполнено.
- Frontend production build прошёл.
- `cargo test --manifest-path udp-agent/Cargo.toml`: 3 теста прошли (IPv4/IPv6 и пустой payload; отказ повреждённых/фрагментированных пакетов; кадры в разбитом потоке).
- `cargo build --manifest-path udp-agent/Cargo.toml` прошёл.
- `python udp-agent/test_echo.py udp-agent/target/debug/secret-tunnel-agent.exe`: PASS, реальные UDP echo для пустого, голосового и 51200-байтного payload, корректный EOF.
- Проверка embedded клиента первоначально остановилась из-за отсутствия NASM в aws-lc-sys; после установки запущена повторно.
- Повторный `cargo check --manifest-path src-tauri/Cargo.toml --features embedded-ssh` прошёл успешно.
- Полная debug-сборка потребовала больше места на D:. Каталог `src-tauri/target` перенесён в `%USERPROFILE%\.cache\secret-tunnel-target` с junction на прежнем пути; сборка продолжена с сохранёнными артефактами.
- В CI добавлены Windows check embedded-конфигурации и проверки UDP-агента на Windows/macOS. Удалённый CI в этой сессии не запускался.
- `cargo build --manifest-path src-tauri/Cargo.toml --features embedded-ssh` завершился успешно. Windows debug executable: `src-tauri/target/debug/secret-tunnel.exe` (22 976 000 байт). UI и реальное подключение этой сборки пока не проверены.
- `cargo test --manifest-path src-tauri/Cargo.toml --features embedded-ssh --lib`: 3 теста прошли, ошибок нет.
- При запуске raw `cargo build` debug EXE выявлена зависимость от `devUrl`: без Vite окно показывает ERR_CONNECTION_REFUSED. Для самостоятельного EXE использовать `npm run tauri -- build --debug --no-bundle --features embedded-ssh` (или release через Tauri CLI), который включает встроенный frontend. Для разработки использовать `npm run tauri:dev`.
- Сборка через Tauri CLI завершилась успешно; окно запущено и дерево доступности подтверждает загрузку интерфейса с `http://tauri.localhost/`, режим System OpenSSH, выбранный профиль и SOCKS 127.0.0.1:1080. Vite после этого остановлен.
- SSH-аутентификация пользовательским ключом успешно проверена отдельно через WSL и Windows OpenSSH. Реальные реквизиты сохранены только в локальном config.json вне репозитория; приватный ключ скопирован в пользовательский .ssh с ограниченным ACL.
- После запуска пользователем TCP-туннель подтверждён: 127.0.0.1:1080 слушает ssh.exe, его ParentProcessId совпадает с процессом клиента. Через SOCKS5 с удалённым DNS успешно выполнены HTTPS-запросы: example.com — HTTP 200, 577 байт; Cloudflare test download — HTTP 200, 1 048 576 байт за 1,14 с. Это разовая проверка доступности, не длительный тест стабильности.
- Пустой график в System OpenSSH на Windows объясняется `sample_process_traffic`: реализация вне macOS возвращает `Ok(None)`. Передача данных исправна, измерение пока отсутствует. Для графика нужен локальный учитывающий relay либо платформенный sampler; TCP embedded-движка уже имеет внутренние счётчики, но требует отдельной интеграционной проверки.
- Исправлено создание консольных окон в Windows: все фоновые команды ssh/curl используют CREATE_NO_WINDOW; GUI subsystem включён также для debug EXE. Проверка `cargo check --features embedded-ssh` прошла. Работающий старый процесс сохраняет прежнее поведение до замены клиента.
- Новая preview-сборка запущена с System OpenSSH: дочерний ssh слушает 1080, HTTPS через него вернул 200. Автозапуск временно включался для проверки и затем восстановлен в false. Визуальное отсутствие кратковременного окна терминала автоматически не подтверждено из-за недоступного захвата окна.
- Добавлен локальный TCP relay для счётчиков System OpenSSH на всех ОС. SSH слушает внутренний loopback-порт, клиентский SOCKS-порт обслуживает relay. Считаются байты TCP потока SOCKS (включая negotiation и TLS), не encrypted SSH wire traffic. Лимит 256 соединений, half-close и закрытие активных потоков при stop.
- Реальный тест relay 1081 → рабочий SSH SOCKS 1080 → HTTPS Cloudflare: HTTP 200, payload 1 048 576 байт; счётчики relay RX=1 056 769, TX=494. Тестовый relay после проверки завершён, порт 1081 освобождён. Первая проверка выявила наследование nonblocking accepted socket в Windows; исправлено явным set_nonblocking(false), добавлен регрессионный тест пауз между запросами.
- После исправления прошли все 6 тестов библиотеки (3 UDP protocol, 3 TCP relay). Собран отдельный `src-tauri/target/debug/SecretTunnel-traffic.exe` со встроенным frontend, скрытыми консольными процессами и новым relay. График в UI этой сборки ещё требует проверки после переключения с работающей preview-сборки.
- UDP-агент установлен в домашний каталог серверного пользователя без sudo; реальный тест Windows embedded backend прошёл для TCP HTTPS и UDP DNS в одной SSH-сессии. Подробности: [SERVER-UDP-SETUP.md](SERVER-UDP-SETUP.md). После изменения exec-команды на явный пользовательский путь агента собран `src-tauri/target/debug/SecretTunnel-udp.exe`; повторные 6 тестов библиотеки прошли.
- Добавлена экспериментальная вкладка «Приложения» и адаптер ProxyBridge/WinDivert (WFP без TUN). Frontend собран, 8 unit tests прошли. Userspace CLI отдельно собран из проверенного upstream revision с parent-EOF cleanup, `--version` работает без драйвера. Драйвер не загружен: защита Windows заблокировала официальный WinDivert zip при чтении/распаковке. Обход блокировки и исключения защиты не применялись.
