# Доменные правила (2026-11-08)

Вкладка **Домены** задаёт regex-правила для новых TCP/UDP-соединений всех приложений. Для каждого правила доступны включение, маршрут «В туннель»/«Напрямую», изменение порядка, удаление и счётчики. Проверка домена работает до сохранения и не выполняет сетевой запрос.

## Приоритет

1. Собственный SSH-транспорт и движок обходят перехват.
2. Первое включённое доменное правило с совпадением.
3. Выбранные приложения — в SOCKS туннеля.
4. Остальные соединения — напрямую.

Таким образом, доменное DIRECT исключение работает и для приложения, выбранного целиком. Доменное TUNNEL правило работает и для приложения, не выбранного в списке. Выключенное правило не влияет на маршрут. После применения переподключите приложение: существующие TCP-сессии и UDP-потоки сохраняют прежний маршрут.

## Синтаксис

Общий Rust-модуль `routing-engine` используется Tauri-командой проверки и нативным ProxyBridgeCore через FFI. Это исключает расхождения между JavaScript regex и фактическим движком. Совпадение применяется к **целому доменному имени**, по умолчанию без учёта регистра:

| Выражение | Совпадает |
|---|---|
| `example\.com` | Только example.com |
| `(?:.*\.)?example\.com` | example.com и поддомены |
| `(?:example\.com|example\.org)` | Два конкретных домена |
| `[a-z]{1,4}\.example\.com` | Короткие поддомены |

Используется Rust regex: без lookaround и обратных ссылок; ограничены размер выражения (1024 байта), компилируемого автомата и количество правил (128). ID правил уникальны. Проверяются также выключенные правила. Домен для теста вводится без схемы, пути и порта; IDN — в punycode.

Regex кодируется UTF-8 hex с префиксом `stregex:` в TargetDomains: запятые, точки с запятой, JSON escaping и нормализация списков upstream не меняют выражение. В native AddRule есть повторная проверка. CLI завершает запуск при отказе добавить любое правило. Старый комплект без маркера `domain-regex-v1` отклоняется при наличии доменных правил.

## Счётчики и ограничения

В нативной обработке IPv4/IPv6, после корректировок маршрута для локальных/служебных адресов, выдаётся `[ST_ROUTE]`: native rule ID, маршрут и hex-домен из DNS-кэша. Используется существующее устранение повторных записей соединений ProxyBridge. Считаются **события решений маршрутизации**, а не пакеты, HTTP-запросы или успешная доставка сервером.

- «Совпадений» — наблюдаемые события, домен которых подходит выражению, включая выключенные и перекрывающиеся правила.
- «В туннель»/«Напрямую» — события, где именно это правило победило и движок выбрал соответствующий маршрут.
- Неизвестный домен считается отдельно; маршрутизация следует списку приложений.
- Счётчики относятся к последнему применённому набору, сохраняются после остановки и сбрасываются при новом запуске перехвата. Изменения черновика не меняют работающий набор.
- Очередь журнала ограничена; потерянные строки считаются отдельно. При потерях статистика неполна. Размер строки увеличен до 1024, чтобы hex максимального DNS-имени не обрезался.
- В памяти остаются агрегаты, а не история посещённых доменов. Служебные ST_ROUTE строки обрабатываются до privacy-фильтра и не добавляются в Runtime logs.

Домен определяется пассивно по обычным DNS-ответам. Это **не fake-IP DNS**: DoH/DoT, ранее заполненный кэш браузера и несколько доменов с одним IP ограничивают точность. HTTPS URL/path не анализируется. Для предсказуемой проверки отключите защищённый DNS в тестовом браузере и перезапустите его после включения перехвата. Этот режим не обещает строгого разделения сайтов, разделяющих IP.

## Сборка и проверки

`scripts/build-redirect-core.ps1` копирует исходники закреплённой ревизии ProxyBridge в каталог сборки, применяет `patch-domain-engine.py`, собирает Rust staticlib и DLL, затем запускает `check-domain-engine.c`. Оригинальный checkout и драйвер не изменяются. Проверка работает без запуска WinDivert и без изменения активного перехвата.

Новый комплект подготовлен отдельно: `%APPDATA%\secret-tunnel\tools\proxybridge-domains`. Старый комплект остаётся доступен. Серверный UDP-agent менять не требуется.

На этой машине путь к новому комплекту уже выбран в конфигурации для следующего запуска. Выбор приложений сохранён. Клиент: `src-tauri\target\debug\SecretTunnel-domains.exe` (встроенный frontend, Vite для запуска не нужен). Перед переходом остановите старый перехват/туннель и закройте старый клиент, затем запустите новый от администратора.

Проверено локально:

- Production frontend build (TypeScript/Vite).
- Rust unit tests клиента и общего regex-модуля.
- Реальный нативный matcher с DNS-кэшем: IPv4/IPv6, TCP/UDP, direct exception, приоритет, отключение, транспортный обход, неизвестный домен, отказ при неверной regex.
- Headless Edge UI: добавление, ошибка regex, тест домена, маршрут, перестановка, выключение, сохранение и применение (Tauri transport в этом тесте имитируется).

Работающий старый туннель при подготовке не прерывался. Проверка новой DLL на живом трафике должна выполняться после переключения клиента/компонента; нативный matcher-тест не подтверждает сквозную доставку через WFP/SSH.
