# Каталог хостеров — план реализации

Дата: 27 ноября 2026. Рабочая версия приложения: 0.3.36.

## Цель

Помочь выбрать локацию VPS по проверке с устройства пользователя, открыть
предложение у хостера и вернуться в существующий мастер настройки SSH.
Первая версия: два зарубежных и два-три российских провайдера. Покупка
происходит у хостера; тестовый адрес никогда не становится адресом купленного VPS.

## Порядок работ

1. **Источники и небольшой каталог.** Проверить официальные страницы/API
   кандидатов: OVHcloud, ITLDC, Timeweb Cloud, FirstVDS.
   Начать с четырёх провайдеров с достоверными тарифами и тестовыми узлами
   (два зарубежных и два российских).
   Отдельно хранить компанию, локацию, предложение и тестовый адрес.
2. **Обновление предложений.** Реализовать отдельные адаптеры к официальным
   API или структурированным данным страниц; агрегатор использовать только
   при наличии проверяемого источника. Сохранять источник, дату и валюту,
   период оплаты, ограничения трафика, стоимость IPv4 и тип скорости порта.
   Ошибка парсинга не заменяет цену нулём и не делает старые данные свежими.
   Написать тесты на реальные форматы источников и их изменение.
3. **Загрузка каталога.** Один формат JSON для всех клиентов: встроенная
   исходная копия, обновление по HTTPS, ограничение размера, проверка схемы
   и последняя корректная копия для отсутствующей сети. Список обновляется
   отдельно от версии приложения. Подготовить проверяемый ручной/плановый
   процесс обновления данных без публикации нового приложения.
4. **Измерение с устройства.** Ограниченная серия TCP-подключений только к
   опубликованным тестовым узлам: медиана, диапазон, успешные попытки,
   семейство адресов, время проверки. Без выдачи TCP-таймаутов за потери
   пакетов и без скачивания больших файлов. Тест запускается пользователем;
   смена сети отменяет текущий прогон. Не отключать VPN и не подменять
   маршрут измерения скрытно. Прямую проверку при активном собственном VPN
   в первой версии блокировать с понятным объяснением.
5. **Экран и мастер.** «Каталог серверов» отдельным разделом и на экране серверов и из выбора
   «Пока нет сервера» в мастере. Общие данные и формулировки в desktop,
   Android и iOS; сортировка по измеренной задержке, фильтры по расположению,
   карточки с условиями тарифа, источником и датой. Переход к заказу и
   кнопка возвращения в мастер после покупки. Поддержать обе темы.
6. **Проверка.** Тесты парсеров/валидации и сетевой проверки с локальными
   фикстурами; проверки сборок затронутых платформ. На iOS Simulator
   проверить загрузку, фильтры, замер, ошибки, отмену, переход в мастер,
   светлую/тёмную тему и сохранение существующих профилей. Ограничения
   системного VPN симулятора не выдавать за проверку на устройстве.
7. **Результат.** Записать проверенные источники, результаты и оставшиеся
   ограничения. Остановиться на локальной ветке с тестовой сборкой: bump,
   push, публикация каталога и релиз в эту задачу не входят.

## Условия приёмки

- В списке есть сопоставимые реальные предложения и четыре провайдера либо
  явно объяснена невозможность достоверно получить конкретное предложение.
- У каждой цены и скорости есть источник и дата. Скорость порта хостера
  отделена от измеренной задержки; это не обещание пропускной способности.
- Валюта и период оплаты видны; акции, продление и доплаты не смешиваются.
- Некорректный/недоступный источник оставляет последнюю корректную карточку
  с её прежней датой и сообщением о проблеме.
- Замеры не идут в фоне без действия пользователя, не используют закрытые
  ключи, не сканируют произвольные порты или локальные адреса из каталога.
- Результат привязан к текущему прогону/сети; отменённый замер не меняет новый.
- Заказ открывает сайт хостера. Мастер просит фактические данные купленного
  сервера и не подставляет публичный тестовый IP.

## Фактическое выполнение

- Реализован общий Rust-модуль, четыре адаптера официальных источников,
  встроенный/обновляемый JSON, отдельный кэш и процесс подготовки данных.
- Провайдеры: OVHcloud (Страсбург), ITLDC (Амстердам), Timeweb Cloud
  и FirstVDS (Москва). Повторное получение всех четырёх источников прошло.
- Экран подключён к списку серверов и мастеру desktop/Android/iOS.
  Сохранение SSH-профилей и ключей не используется каталогом.
- Пройдены Python/Rust/XCTest, сборки UI/Android mobile/TV и lint.
  На iPad Simulator и Android 14 Emulator выполнены реальные TCP-замеры.
- Публичная публикация JSON и выпуск приложения не выполнялись.
  Перед общим релизом нужны публикация каталога, проверка Windows в CI
  и обновление публичной инструкции/снимков экранов под новый интерфейс.

Источники, архитектура, результаты и ограничения:

## Дополнение: автоматизация и расширение списка

По последующему запросу пользователя разрешены публикация данных и настройка
ежедневного GitHub Actions. Это отдельное изменение без релиза приложения.
Добавлены IPHoster, Vultr и Hetzner; отсутствие тестового узла не исключает
провайдера из каталога и не подменяется замером сайта компании.
