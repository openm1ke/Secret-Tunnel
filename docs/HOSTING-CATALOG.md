# Каталог хостеров: первая реализация

Ветка `codex/hosting-catalog`, база — 0.3.36. План:
[HOSTING-CATALOG-PLAN.md](HOSTING-CATALOG-PLAN.md).

## Пользовательский сценарий

Отдельная вкладка «Каталог» на Android/iOS, пункт «Каталог серверов»
в боковом меню desktop/Android TV или «Мастер настройки → Пока нет сервера».
На мобильных устройствах «Статистика» перенесена в «Ещё»; на desktop/TV
её пункт сохранён. Каталог из мастера iOS открывается на весь экран. Каталог позволяет отфильтровать Россию/зарубежные локации,
измерить задержку и расположить предложения по результату.

«Сайт хостера» открывает его сайт. Приложение не оформляет
покупку и не передаёт хостеру ключи. После покупки «Сервер уже куплен —
настроить SSH» возвращает в мастер. Публичный тестовый IP не подставляется
в подключение. Существующие профили и ключи не меняются.

## Данные и источники

Одна встроенная копия: `site/catalog/hosting-v1.json`. В ней раздельно
указаны провайдер, страна компании (если известна), локация VPS, предложение,
цена в минимальных денежных единицах, валюта, характеристики, условия,
источники цены и тестового узла, дата проверки и ошибка обновления.

| Провайдер / локация | Источник цены | Извлечение |
| --- | --- | --- |
| OVHcloud / Страсбург | [публичный каталог IE](https://eu.api.ovh.com/1.0/order/catalog/public/vps?ovhSubsidiary=IE) | Точный `vps-2025-model1`, обычное помесячное продление без обязательства; характеристики из `products[].blobs.technical`. Установка и годовая предоплата не участвуют в выборе цены. Цена без НДС, базовая. |
| ITLDC / Амстердам | [VDS](https://itldc.com/en/vds/) | Astro props карточки `AMS NVMe VDS 1G`, `EU1.AMS`. Скорость порта отсутствует в этих данных, поэтому не придумана. Страна компании не подтверждена и не используется для определения локации. |
| Timeweb Cloud / Москва | [VDS/VPS](https://timeweb.cloud/services/vds-vps) | Граф Nuxt/devalue: точный `Cloud MSK 15`, `msk_nvme`. Базовая цена, IPv4 и дополнительные услуги уточняются при заказе. |
| FirstVDS / Москва | [VDS/VPS](https://firstvds.ru/products/vds_vps_hosting) | `script[data-tariffs]`, `VDS Прогрев`, KVM/SSD. Обычная цена за месяц; скорость из выбранного бесплатного дополнения «Трафик». NVMe с тем же названием не смешивается с SSD. |

Агрегаторы не понадобились: официальные источники дают проверяемые
структурированные данные. Сайты не исполняются как код и не загружаются
клиентами при просмотре каждой карточки. Нет партнёрских ссылок и пересчёта
валют. Заявленная скорость порта не является замером скорости арендуемого
VPS или гарантией скорости SSH. Комиссии, акции, доступность оплаты и
финальная стоимость проверяются пользователем в заказе.

Тестовые узлы:

- [OVHcloud Strasbourg](https://sxb1-sbg.speedtest.network.ovh.net/): опубликованный speedtest-узел, TCP 443.
- [ITLDC Looking Glass](https://itldc.com/en/lg): эталонный IPv4 Амстердама, TCP 80.
- [Timeweb Speedtest](https://timeweb.cloud/tools/speedtest): московский узел `msk.speedtest.timeweb.ru`, TCP 443, опубликован в модуле страницы.
- [FirstVDS Москва / ix](https://ix.lg.firstvds.ru/): опубликованный **тестовый IPv4**, TCP 443. `lg.firstvds.ru` — портал на другом хостинге; измерять его как московский VPS нельзя.

## Обновление без релиза приложения

При открытии клиенты показывают встроенную/сохранённую копию и пробуют
обновить её с `https://openm1ke.github.io/Secret-Tunnel/catalog/hosting-v1.json`.
Есть ручная кнопка «Обновить каталог». Ошибка сети оставляет карточки на
месте. Кэш лежит отдельно от настроек SSH, записывается заменой файла;
неверный формат, дубли, неожиданные валюты, локальные тестовые адреса,
неподходящие порты, неизвестная схема и откат даты отвергаются. Размер
ограничен 256 KiB; HTTPS-редиректы запрещены. Данные старше недели помечаются
предупреждением. Доверие к обновлениям опирается на HTTPS и контроль сайта;
подпись каталога отдельным ключом — последующее усиление перед расширением
редакторов/партнёров.

Обновить цены:

```sh
python3 scripts/update-hosting-catalog.py --output /tmp/hosting-v1.json
cargo run --manifest-path hosting-catalog/Cargo.toml --locked --example catalog -- validate /tmp/hosting-v1.json
```

Адаптеры используют официальные API/встроенные данные страниц. Один
источник скачивается один раз; лимит 16 MiB, таймаут 30 с. При ошибке
сохраняются прежние факты **и прежняя дата**; устанавливается `update_error`.
Скрипт возвращает ненулевой код для проверки изменившегося источника.
Локации и тестовые узлы редактируются в JSON и проверяются по указанным
официальным ссылкам, а не угадываются адаптером цены.

Ежедневная автоматизация и семь адаптеров описаны отдельно:
[HOSTING-CATALOG-AUTOMATION.md](HOSTING-CATALOG-AUTOMATION.md).
Она сохраняет последний опубликованный каталог, публикует частично успешные
обновления, сообщает об ошибках через статус Actions и проверяет публичный JSON.
Карточки без тестового TCP-узла отображаются без замера и не создают сетевых подключений.

## Смысл замера и ограничения

Общий Rust-модуль `hosting-catalog` обслуживает desktop, JNI и iOS C API.
Запросы выполняются в рабочих потоках. Только ручной запуск: пять коротких
TCP-подключений на узел, медиана/минимум/максимум и число ответов. Параллельно
не больше восьми выбранных узлов, один прогон на процесс. DNS имеет срок 3 с,
каждая попытка — общий срок 2 с, подключения закрываются сразу. После первого
успеха закрепляется адрес/семейство; время DNS не входит в TCP-задержку.

Это **не ICMP**, не замер пропускной способности, не потеря UDP-пакетов и
не проверка SSH на порту 22. Таймаут TCP не объявляет VPS неработающим.
Для реальной оценки скорости и стабильности нужна проверка уже купленного
VPS под нагрузкой. Расположение тестового узла и будущего VPS может отличаться.

При собственном активном туннеле проверка блокируется. Другой системный
VPN/прокси может изменить маршрут — автоматического его отключения нет.
Прежде чем вручную останавливать туннель ради замера, нужно закрыть
защищаемые приложения: настройка блокировки сохраняется, но сама защита
после остановки VPN может прекратиться. Каталог не меняет это поведение.
Fake-IP `198.18.0.0/15`, локальные, служебные, mapped/NAT64 и прочие
транслированные/непубличные ответы DNS отвергаются до подключения; подключение идёт к уже
проверенному IP. Но прозрачный прокси с публичным DNS-ответом распознать по
одному TCP-handshake нельзя: результат характеризует текущий маршрут ОС.

Идентификатор прогона защищает от запоздавшего результата и отмены,
пришедшей до запуска рабочего потока. iOS NWPathMonitor/Android network
callback и проверка изменения локального маршрута в общем модуле отменяют
замер; desktop также слушает online/offline. Изменение сети с тем же
локальным адресом, которое ОС не сообщила, может остаться незаметным.
Сворачивание/закрытие экрана отменяет измерение. Результаты не сохраняются
как постоянная характеристика хостера.

В Android 14 Emulator установлена отдельная `Secret Tunnel Test`; каталог
и JNI работают, реальные подключения дают ответы. Исходные тестовые
SSH-профили сохранились. Замеры Android-эмулятора заметно менялись под
нагрузкой сборок, поэтому их нельзя приравнивать к физическому телефону.
Искусственное ограничение сети эмулятора выключено (проверено console
`network status`). Реальный переход Wi-Fi/мобильная сеть в этом прогоне
не выполнялся. Он требует телефона. В симуляторе проверена ручная отмена;
обработчики смены сети реализованы, но физический обрыв сети не прогонялся.
Проверка каталога не является проверкой реального iOS VPN.

Сборки и снимки находятся локально в `artifacts/hosting-catalog/` (не в git):
APK mobile/TV и ZIP приложения для **iOS Simulator**, не для установки на iPad.
Подпись для физического iOS-устройства и Windows-сборка здесь не проверялись.
У существующих серверов приложения настройки не менялись. Пушей, тегов,
публичных релизов и публикации сайта не было.

До общего релиза: опубликовать JSON, прогнать Windows CI и обновить
публичную справку/снимки экранов после утверждения интерфейса. Отдельное
сравнение IPv4/IPv6 и поддержка IPv6-only/NAT64 тестовых сетей остаются
дальнейшими улучшениями: текущий каталог использует прежде всего IPv4-узлы,
а транслированные адреса не измеряет. Это не меняет IPv6-политику SSH-туннеля.

## Обновление интерфейса: отдельный раздел

27 ноября 2026 каталог перестроен в отдельную страницу. На iPad и широком
окне — две колонки, на телефоне и узком окне — одна. В горизонтальном
iPad фильтры и действия размещаются в один ряд. В desktop каталог использует
всю рабочую область; журнал на этой странице скрыт. Из мастера открывается
полноэкранный просмотр, без небольшой карточки поверх приложения.

Флаг обозначает **страну тестового сервера**. Страна компании показывается
отдельно в подробностях, если подтверждена. Цена и TCP-задержка — самые
крупные значения; далее скорость порта, CPU/RAM/диск и «Сайт хостера».
«Подробнее» раскрывает тариф, налоги/доплаты, источник, дату и подробный
результат проверки. Короткое уточнение цены (`price_note`, необязательное
поле схемы v1) остаётся видимым: «Без НДС» нельзя прятать вместе с условиями.

Используются существующие темы, системные шрифты и компоненты. Для Windows
переиспользован встроенный шрифт флагов Twemoji Country Flags; внешних
картинок для флагов не требуется. Для Android сохранены нативные кнопки,
контрастный фокус пульта и отдельный экран Activity.

Проверки редизайна: 8 тестов общего каталога (включая старый JSON без
`price_note` и ограничение длины), 4 теста парсеров, 4 XCTest, TypeScript/Vite,
проверка desktop Rust и сборка/lint Android mobile/TV. Desktop проверен
Playwright с тестовым IPC: четыре карточки, фильтр страны, раскрытие с
клавиатуры, целевой URL хостера, две темы и узкое окно без переполнения.
Замеры в desktop-предпросмотре — **фикстура**, не сетевой бенчмарк.
Снимки и новые тестовые сборки — `artifacts/hosting-catalog-v2/`, вне git.

Финальная визуальная проверка редизайна выполнена на iPhone SE (3rd gen),
375 pt, iPad Pro 11 (M5) в двух ориентациях и Android 14 Emulator.
В нативных клиентах повторно проверены реальные TCP-замеры и раскрытие
условий. Переключатель сортировки после замера находится над карточками.
Профили/ключи не менялись. Публикация данных вынесена в отдельный процесс Actions.
