# Secret Tunnel для iOS/iPadOS (экспериментально)

Нативный клиент в `ios/`: приложение SwiftUI и расширение **Packet Tunnel** (`NEPacketTunnelProvider`), iOS/iPadOS 15+.

Цепочка такая же, как на Android: `utun → hev-socks5-tunnel → Rust SOCKS5 ([::1]:10808) → SSH → secret-tunnel-agent`. Rust-ядро общее (`tunnel-core`, C API в `ios/native`). Сокеты самого расширения (SSH-соединение) не идут через его туннель, поэтому `protect()` из Android не нужен.

Проверено 10 ноября 2026 на iPad Air 2 (iOS 15.8.8): VPN для всего устройства, speedtest.net 27 Мбит/с скачивание и 18 Мбит/с загрузка через SSH-сервер, память расширения до 8,4 МБ.

Особенности, найденные на устройстве:

- SOCKS слушает `::1`, а не `127.0.0.1`. hev всегда открывает IPv6-сокеты, и v4-mapped `::ffff:127.0.0.1` внутри расширения не подключался: hev отбрасывал все UDP (DNS) и TCP-сессии.
- Лимит мультиплексора 1024 потока, окно UDP равно окну TCP (64 КБ). При лимите 256 новые соединения отклонялись (`Receive buffer budget reached`): бюджет приёма был равен «лимит × 64 КБ», а каждый UDP-поток резервировал на агенте 128 КБ. С 11 ноября 2026 бюджет рассчитан на наибольшее окно, а DNS-ассоциации закрываются через 5 секунд; для полной ёмкости на стороне сервера нужен пересобранный агент.
- С агентом, который объявляет `elastic_tcp`, окно TCP равно 256 КБ и растёт от 64 КБ, пока канал быстрый. Поток с остановившимся получателем может держать в очереди до 256 КБ, поэтому при многих зависших загрузках следите за строкой `memory` в журнале расширения.
- В расширении включена диагностика в системный журнал: самопроверка SOCKS, счётчики hev, память. Читать: `idevicesyslog -u <UDID> | grep "PacketTunnel\["`.

## Ограничения iOS

- **Туннель для всего устройства.** Выбрать отдельные приложения нельзя: per-app VPN на iOS работает только на устройствах под MDM и только для управляемых приложений.
- **Симулятор.** На iOS Simulator 27.2 системный `nehelper` недоступен. Сохранение профиля завершается ошибкой `IPC failed` до запуска Packet Tunnel. В симуляторе доступны проверка входа и агента, а также тест HTTPS через локальный SOCKS5. Системную маршрутизацию проверяйте на iPhone или iPad.
- **Подпись.** Нужен платный аккаунт Apple Developer: право Network Extension для Personal Team недоступно.
- **Память расширения** на iOS ограничена (десятки МБ), поэтому буферы UDP и лимиты сессий уменьшены по сравнению с Android.
- **IPv6 захватывается всегда.** В utun и hev настроены IPv4 и IPv6 с маршрутами по умолчанию. Если проверка IPv6-выхода сервера не проходит, числовые IPv6-адреса отклоняются в общем SOCKS-ядре для соответствующего транспорта; прямого запасного соединения нет. Проверки TCP и UDP выполняются через SSH при каждом новом подключении. Поэтому сервер с одним IPv4 продолжает обслуживать IPv4, не оставляя IPv6 устройства вне VPN.
- Для полного туннеля включены `includeAllNetworks` и `excludeLocalNetworks = false`: приложение не должно обходить VPN, явно выбрав Wi-Fi. Исключения, которыми управляет сама iOS (в частности, служебный трафик и соединение с VPN-сервером), сохраняются. При цепочке серверов адресом входа считается первый SSH-узел. Ручная остановка VPN возвращает обычную маршрутизацию; это не системный always-on VPN.

## Сборка

Требуются Xcode, XcodeGen, Rust (`aarch64-apple-ios`, `aarch64-apple-ios-sim`).

```bash
scripts/build-ios.sh sim                      # симулятор, без подписи
ST_DEVELOPMENT_TEAM=<TeamID> ST_BUNDLE_PREFIX=<ваш.префикс> scripts/build-ios.sh device
```

Без `ST_DEVELOPMENT_TEAM` сборка для устройства не подписывается (только проверка компиляции и линковки). Xcode с `-allowProvisioningUpdates` сам создаёт App ID, App Group `group.<префикс>.ios` и профили.

### Установка на iOS 15

Xcode 27 не предлагает устройства с iOS 15 как цель запуска, поэтому подписанное приложение ставится через libimobiledevice:

```bash
brew install ideviceinstaller
mkdir -p /tmp/st-ipa/Payload && cp -R ios/build/DerivedData/Build/Products/Release-iphoneos/SecretTunnel.app /tmp/st-ipa/Payload/
(cd /tmp/st-ipa && zip -qry SecretTunnel.ipa Payload)
ideviceinstaller -u <UDID> install /tmp/st-ipa/SecretTunnel.ipa
```

UDID устройства должен быть в профиле разработки (Certificates, Identifiers & Profiles → Devices). Журнал устройства: `idevicesyslog -u <UDID> | grep PacketTunnel`.

## Проверка

В тестовой сборке откройте «Ещё» → «Серверы» → «Мастер настройки». Для уже купленного сервера укажите адрес, SSH-порт, пользователя и готовый приватный ключ либо пароль. Перед отправкой пароля мастер предлагает подтвердить отпечаток сервера, создаёт отдельный Ed25519-ключ и проверяет повторный вход по нему. Пароль не сохраняется. При отсутствии агента доступна его установка с проверкой SHA-256. Журнал показывает текущий этап и причину ошибки. Поддерживаются Linux x86_64, обычная SSH-аутентификация по паролю и ключи без парольной фразы. При включённом VPN настройка заблокирована.

Можно сохранить несколько серверов с отдельными ключами. В разделе «Серверы» нажмите «Использовать» у нужного профиля, затем подключитесь на главной. Для смены сервера сначала остановите VPN. Прежнее одиночное подключение сохраняется при добавлении новых профилей.

22 ноября 2026 на iPad Air 2 (iPadOS 15.8.8) проверено последовательное подключение к двум серверам: вход с отдельными ключами устройства, агент 0.3.31, системный VPN и HTTPS-запрос с проверкой адреса выхода. Секреты передавались по USB в приватный контейнер приложения и не включались в IPA. Импорт и автоматический прогон по аргументам запуска доступны только в сборках Debug.

Ручная настройка также доступна:

1. На экране «Ещё» → «Серверы» введите адрес, порт и пользователя SSH, затем импортируйте приватный ключ (OpenSSH, без passphrase) через «Файлы».
2. «Получить отпечаток сервера», сверьте с `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` на сервере и подтвердите.
3. «Проверить вход и агент»: должен пройти вход по ключу и найтись `secret-tunnel-agent`.
4. На iPhone или iPad нажмите «Подключить» на главной и разрешите добавление VPN-конфигурации. Откройте сайт проверки IPv4 в Safari. Должен отображаться адрес сервера, а счётчики в приложении должны расти.
5. На iOS 17 и новее откройте «Скорость» и нажмите «Начать тест». Он измеряет загрузку и отправку через локальный SOCKS5. Тест передаёт до 3 МБ и доступен в симуляторе с настроенным сервером.

### Проверка IPv6

`TunnelNetworkPolicyTests` проверяет оба маршрута, параметры полного туннеля, конфигурацию hev и выбор первого узла цепочки. Симулятор не подтверждает системную защиту от обхода — для неё нужен физический iPhone/iPad.

Debug-сборка поддерживает `--ipv6-device-checks` после импорта одноразовых профилей `IPv6 QA`, `IPv6 QA Relay` и `IPv6 QA Chain` через `--import-profiles`. Файл `Documents/ipv6-device-fixture.json` задаёт `physical_host`, `physical_port` и `expect_ipv6`; закрытых ключей в исходниках и приложении нет. Прогон проверяет TCP/UDP к IPv4 `203.0.113.10` и IPv6 `2001:db8::10`, порт 27150, через изолированный агент. Дополнительно проверяется IPv6-соединение, привязанное к Wi-Fi: контроль до VPN должен пройти, а при работающем VPN — не пройти. `--ipv6-chain` включает проверку цепочки. Результат находится в `Documents/ipv6-device-checks.json`, VPN в конце останавливается. Адреса примера должны принадлежать изолированному стенду, а не публичным серверам.
