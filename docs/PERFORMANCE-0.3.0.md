# Проверка Secret Tunnel 0.3.0 — 9 ноября 2026

Windows измерен в запущенной debug-сборке desktop-клиента с встроенным SSH и SOCKS5 на `127.0.0.1:1080`. У процесса наблюдалось одно установленное SSH-соединение. На realme RMX3630 с Android 14 подписанный release APK обновил установленную версию 0.2.3 с сохранением профиля сервера и девяти выбранных приложений. Выбранный тестовый UID прошёл через Android VPN, исключённый UID остался на прямом маршруте. HTTPS, DNS и UDP сработали в обоих режимах. Внешние адреса выхода различались.

В каждой серии четыре параллельные HTTPS-загрузки по 4 МиБ. UDP-пробы отправлялись к DNS-резолверу без загрузки и пока выполнялись загрузки. RTT измерен от отправки запроса до получения ответа. Это короткие замеры на рабочей сети и одном SSH-сервере.

| Стенд | TCP, Мбит/с | UDP p95 без нагрузки → под нагрузкой | Ответы UDP без нагрузки / под нагрузкой | CPU приложения, доля одного ядра |
| --- | ---: | ---: | --- | ---: |
| Windows, SOCKS5 | 27,6 | 58 → 121 мс | 48/48, 48/48 | 13,7% |
| Android, выбранный UID через VPN | 30,2 | 60 → 139 мс | 48/48, 48/48 | 23,1% |
| Android, исключённый UID напрямую | 119,0 | 37 → 115 мс | 48/48, 20/20 | 0,6% у VPN в фоне |

На Windows суммарная private memory процесса приложения и WebView2 составила 182–184 МиБ по снимкам до и после прогона. На Android PSS процесса VPN составил 57–63 МиБ. CPU усреднён за весь прогон, включая UDP без нагрузки. Эти показатели памяти имеют разные определения на двух ОС.

Повторить Windows-прогон можно командой `python scripts/benchmark-socks.py --port 1080`. На Android используется `ProbeActivity` с параметром `--ez benchmark true` для выбранного и исключённого тестовых APK из модуля `traffic-probe`. Сырые результаты текущей сессии лежат в `artifacts/agent-preflight-2026-11-09/`.

Проверки выпуска включали 24 Windows-теста, 16 тестов `stream-mux`, 16 тестов `tunnel-core`, 7 тестов агента и 9 Android unit-тестов. Подписанный APK проверен по сертификату установленного приложения и на обе ABI. Android lint завершился без ошибок. Агент Linux x86_64 прошёл TCP half-close, UDP с пустыми, голосовыми и 51 200-байтными пакетами, а также тест изоляции 24 ассоциаций. Установщик прошёл проверку установки, отказа при неверном SHA256 и отката.

Следующий прогон использует контролируемые TCP/UDP echo-цели и повторные серии. Для выбора настройки нужны задержка в очереди агента, возраст UDP-пакетов и доля пропускной способности каждого потока. Сравним справедливое планирование и короткие UDP-очереди по p95/p99, потерям и скорости TCP.
