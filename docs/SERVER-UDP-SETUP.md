# Установка и проверка UDP-агента — 7 ноября 2026

Обновление v0.2.3: новый клиент запускает агент с `--multiplex`, который объявляет STUDP002. Один SSH exec-канал обслуживает независимые UDP-ассоциации с отдельными идентификаторами и сокетами. Без этого флага агент сохраняет STUDP001 для старых клиентов. Для исправления лимита параллельных загрузок нужно обновить и клиент, и пользовательский бинарник агента; менять MaxSessions, sshd, firewall или открывать публичный порт не требуется. Описание ниже фиксирует исходную установку и проверки версии STUDP001.

## Изменения на сервере

Установка выполнена по SSH от существующего пользователя, без sudo:

- `~/.local/bin/secret-tunnel-agent` — release-бинарник, права 700.
- `~/.local/share/secret-tunnel/build` — исходники агента, общий протокол и результаты сборки.
- `~/.local/share/secret-tunnel/rustup` и `cargo` — изолированный Rust toolchain с минимальным профилем. Системный PATH и shell startup-файлы не изменялись.
- `~/.local/share/secret-tunnel/rustup-init.sh` — установщик toolchain.

SHA256 установленного бинарника:
`8e90b41634591e39b0c1640257b747aeedea086b6c106b2d8d192abdf5389871`.

Системные пакеты, sshd, firewall, существующие службы и конфигурация Xray/туннелей не изменялись. Xray был active до и после установки. Для агента не создавались systemd unit и входящий сетевой порт.

Агент запускается по требованию командой `exec "$HOME/.local/bin/secret-tunnel-agent"` в exec-канале существующей SSH-сессии клиента. Один процесс обслуживает одну SOCKS UDP-ассоциацию. При закрытии ассоциации канал закрывается, stdin агента получает EOF, процесс завершается.

## Выполненные проверки

1. На Linux x86_64: `cargo test --locked --manifest-path udp-agent/Cargo.toml` — 3 теста прошли; release build прошёл.
2. Диагностический Windows executable использовал тот же `embedded_ssh.rs` и `udp_protocol.rs`, что GUI-клиент, с проверкой SSH host key.
3. Локальный SOCKS на 1082: одновременно TCP HTTPS к example.com (HTTP 200) и 8 UDP DNS-запросов к 1.1.1.1 (все ответы корректные).
4. При закрытии управляющего TCP SOCKS UDP-порт перестал отвечать.
5. У диагностического процесса обнаружено ровно одно внешнее ESTABLISHED TCP-соединение к SSH-серверу. Дополнительного клиентского UDP-транспорта до сервера нет.
6. Счётчики встроенного транспорта после проверки RX=5915, TX=907; статус завершения SSH до остановки — None (сессия жива). Тестовый клиент штатно остановлен.
7. После завершения ассоциации на сервере не осталось процессов установленного агента.

## Как повторить

Из корня проекта собрать диагностический клиент:

```powershell
cargo build --manifest-path src-tauri/Cargo.toml --features embedded-ssh,tauri/custom-protocol --example check_embedded
```

Запустить его с путём к локальному конфигу. Используется выбранный сервер из конфигурации, создаётся отдельный SOCKS 127.0.0.1:1082 на 40 секунд:

```powershell
src-tauri/target/debug/examples/check_embedded.exe "$env:APPDATA/secret-tunnel/config.json"
```

Пока напечатано READY, в другом терминале:

```powershell
python scripts/check_socks_udp.py 1082
```

Для GUI требуется новая UDP-сборка и SSH engine `Embedded Rust SSH`. System OpenSSH остаётся TCP-only. Локальный SOCKS UDP ещё не означает автоматический перехват Discord: выбор приложений Windows будет отдельным этапом.

Не проверены голос Discord, длительная нагрузка, восстановление после разрыва и качество при потерях TCP. Текущая проверка подтверждает работоспособность транспорта, но не гарантирует качество голоса.
