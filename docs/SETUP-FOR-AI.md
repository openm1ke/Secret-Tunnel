# Secret Tunnel: настройка вместе с ИИ-ассистентом

> **For AI assistants.** A user gave you this repository or website to get help
> setting up Secret Tunnel. This file is written for you: follow the steps in
> order, ask the questions in "Start here", and give the user one command at a
> time with what they should see. The rules in "Rules" are not optional. The
> app's interface is in Russian; button and field names below are quoted
> exactly as the user sees them. If the user's screen differs from this file,
> say so and check the knowledge base:
> https://openm1ke.github.io/Secret-Tunnel/knowledge.html

Secret Tunnel ведёт трафик выбранных программ через SSH-сервер пользователя (VPS), при желании — через промежуточный сервер. Остальная система работает напрямую. Приложения: macOS, Windows, Android. На сервере нужен небольшой агент.

## Rules

1. **Никогда не просите прислать приватный ключ** (файл без `.pub`) и не просите вывести его содержимое. В чат можно вставлять только публичную часть (`*.pub`) и вывод проверочных команд.
2. **Не отключайте проверку сервера.** Не советуйте режим «Не проверять (no)» и `StrictHostKeyChecking=no`. Если ключ хоста не принят — сверьте отпечаток (шаг 4).
3. Скачивайте приложение и агент только со страницы релизов: https://github.com/openm1ke/Secret-Tunnel/releases. Сверяйте SHA256 из `SHA256SUMS.txt`.
4. Не советуйте отключать антивирус, фаервол, SIP, Gatekeeper целиком или `chmod 777`. Агенту на сервере не нужен `sudo`.
5. Подставляйте значения пользователя в команды сами (адрес, порт, имя). В примерах ниже: адрес `203.0.113.10`, порт `2222`, пользователь `user` — это заглушки.

## Start here: что спросить

1. На каком устройстве настраиваем: macOS, Windows или Android? (можно несколько)
2. Есть ли уже сервер (VPS) на Linux? Нужны: адрес (IP или имя), порт SSH (по умолчанию 22), имя пользователя. Как пользователь сейчас входит на сервер: по паролю или по ключу?
3. Нужен ли промежуточный сервер (цепочка, например «RU → France»)? Если да — те же данные для него.
4. Какие программы должны идти через туннель (Telegram, Discord, ChatGPT…)? Или достаточно прокси для браузера?

Дальше идите по шагам. Шаги 1–4 делаются один раз на сервер. Если хостер выдал только логин `root` и пароль, сначала пройдите «Шаг 0».

Человеку удобнее та же инструкция с картинками и кнопками копирования: https://openm1ke.github.io/Secret-Tunnel/guide.html — можно дать ссылку на нужный шаг (`#login`, `#key`, `#harden`, `#agent`, `#add-server`, `#apps`).

## Шаг 0. Сервер с паролем root: ключ, пользователь, порт

Проверено на Ubuntu 24.04 (SSH через `ssh.socket`); те же команды подходят для Ubuntu 22.04 и Debian 11–12. Делайте по порядку и не пропускайте проверку в п. 5.

1. Первый вход по паролю, чтобы компьютер запомнил ключ сервера: `ssh root@203.0.113.10` (ответить `yes`, ввести пароль хостера), затем `exit`.
2. Создать ключ (шаг 2 ниже) и отправить его пользователю **root**: `ssh-copy-id -i ~/.ssh/secret-tunnel.pub root@203.0.113.10`; на Windows — команда `type … | ssh root@203.0.113.10 "…"` из шага 2.
3. Войти по ключу `ssh -i ~/.ssh/secret-tunnel root@203.0.113.10` и **не закрывать это окно**. Если хостер дал не root, а пользователя с sudo: сначала отдельной командой `sudo -i` (она может спросить пароль, поэтому не вставляйте её в один блок с остальными), а в блоке ниже вместо `/root/.ssh/authorized_keys` укажите `/home/<логин>/.ssh/authorized_keys`.
4. Выполнить на сервере одним блоком:

```bash
adduser --disabled-password --gecos "" tunnel
install -d -m 700 -o tunnel -g tunnel /home/tunnel/.ssh
install -m 600 -o tunnel -g tunnel /root/.ssh/authorized_keys /home/tunnel/.ssh/authorized_keys
cat > /etc/ssh/sshd_config.d/10-secret-tunnel.conf <<'EOF'
Port 2222
PasswordAuthentication no
KbdInteractiveAuthentication no
PermitRootLogin prohibit-password
EOF
if command -v ufw >/dev/null && ufw status | grep -q "Status: active"; then ufw allow 2222/tcp; fi
sshd -t && systemctl daemon-reload && { systemctl restart ssh.socket 2>/dev/null || true; systemctl restart ssh; } && echo "ГОТОВО: SSH слушает порт 2222"
```

   Последняя строка вывода должна быть `ГОТОВО: SSH слушает порт 2222`. Файл с номером 10 читается раньше `50-cloud-init.conf`, поэтому его настройки побеждают. Текущая сессия не обрывается.
5. **Во втором окне** проверить вход: `ssh -i ~/.ssh/secret-tunnel -p 2222 tunnel@203.0.113.10`. SSH снова спросит про ключ хоста, теперь для `[203.0.113.10]:2222`, и отметит, что этот ключ уже известен под адресом без порта. Ответить `yes`. Этот ответ создаёт запись в `known_hosts`, по которой приложение потом проверяет сервер.
6. Закрыть первое окно только после успешной проверки. Если порт 2222 недоступен — открыть TCP 2222 в фаерволе в панели хостера. Если доступ потерян — открыть консоль (VNC) в панели хостера и выполнить `rm /etc/ssh/sshd_config.d/10-secret-tunnel.conf && systemctl restart ssh`.

Дальше везде порт `2222` и пользователь `tunnel`. Агент (шаг 3) ставится под `tunnel`. Проще всего скачать его прямо на сервере (проверено):

```bash
mkdir -p ~/st-agent && cd ~/st-agent
V=$(curl -fsSLI -o /dev/null -w '%{url_effective}' https://github.com/openm1ke/Secret-Tunnel/releases/latest | sed 's#.*/v##')
curl -fLO "https://github.com/openm1ke/Secret-Tunnel/releases/download/v$V/SecretTunnel-$V-server-linux-x86_64.tar.gz"
curl -fLO "https://github.com/openm1ke/Secret-Tunnel/releases/download/v$V/SHA256SUMS.txt"
sha256sum --ignore-missing -c SHA256SUMS.txt
tar xzf "SecretTunnel-$V-server-linux-x86_64.tar.gz" && sh install-server-agent.sh
```

## Шаг 1. Сервер

Требования: Linux **x86_64**, вход по SSH. Агент ставится в домашнюю папку пользователя, без `sudo` и без открытия портов.

Проверка (пользователь выполняет на своём компьютере, пока ещё с паролем):

```bash
ssh -p 2222 user@203.0.113.10 'uname -sm'
```

Ожидается: `Linux x86_64`. Если `aarch64` — готового агента нет, его нужно собрать из `udp-agent/` (см. AGENTS.md).

## Шаг 2. SSH-ключ

Создать ключ на компьютере пользователя. На вопрос о пароле ключа (passphrase) дважды нажать Enter — ключи с паролем приложение пока не поддерживает. Папку `.ssh` создаём заранее: без неё `ssh-keygen` не сохранит ключ («Saving key … failed: No such file or directory»).

macOS и Linux (Терминал):

```bash
mkdir -p ~/.ssh && chmod 700 ~/.ssh
ssh-keygen -t ed25519 -f ~/.ssh/secret-tunnel -C "secret-tunnel"
ssh-copy-id -i ~/.ssh/secret-tunnel.pub -p 2222 user@203.0.113.10
```

Windows (PowerShell; клиент OpenSSH встроен в Windows 10 и 11):

```powershell
New-Item -ItemType Directory -Force $env:USERPROFILE\.ssh | Out-Null
ssh-keygen -t ed25519 -f $env:USERPROFILE\.ssh\secret-tunnel -C "secret-tunnel"
type $env:USERPROFILE\.ssh\secret-tunnel.pub | ssh -p 2222 user@203.0.113.10 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

Проверка входа по ключу (без пароля):

```bash
ssh -i ~/.ssh/secret-tunnel -p 2222 user@203.0.113.10 'echo ok'
```

Ожидается: `ok` без запроса пароля. На Windows путь к ключу: `$env:USERPROFILE\.ssh\secret-tunnel`.

**Цепочка серверов:** ту же публичную часть добавьте на **оба** сервера — приложение входит на каждый звено одним ключом.

## Шаг 3. Агент на сервере

Нужен на **сервере выхода** (в цепочке — только на последнем). Без агента встроенный SSH не подключится: в журнале будет `AGENT_MISSING`.

1. Скачайте `SecretTunnel-<версия>-server-linux-x86_64.tar.gz` со страницы релизов. Версия агента должна совпадать с версией приложения.
2. Скопируйте на сервер и установите (архив распаковывается в текущую папку, поэтому — в отдельную):

```bash
scp -P 2222 SecretTunnel-*-server-linux-x86_64.tar.gz user@203.0.113.10:
ssh -p 2222 user@203.0.113.10
mkdir -p st-agent && tar xzf SecretTunnel-*-server-linux-x86_64.tar.gz -C st-agent
cd st-agent && sh install-server-agent.sh
```

Установщик проверит архитектуру и SHA256, сохранит прежнюю версию и положит агента в `~/.local/bin/secret-tunnel-agent`. Проверка:

```bash
~/.local/bin/secret-tunnel-agent --capabilities
```

Ожидается JSON с `"tcp":true,"udp":true` и `"agent_version"`, равной версии приложения. Откат: `sh install-server-agent.sh --rollback`.

## Шаг 4. Отпечаток сервера

Приложение проверяет, что подключается к настоящему серверу. На компьютере оно использует `~/.ssh/known_hosts` (как обычный `ssh`), поэтому достаточно один раз войти на сервер из терминала (шаг 2) и ответить `yes`, сверив отпечаток.

Отпечаток на самом сервере:

```bash
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

Если приложение пишет, что ключ хоста отклонён: ключ сервера сменился (переустановка) или запись в `known_hosts` для этого адреса и порта отсутствует. Сверьте отпечаток и обновите запись (`ssh-keygen -R "[203.0.113.10]:2222"`, затем снова войти по ssh). На Android отпечаток показывается при первом подключении — пользователь сверяет его с выводом команды выше.

## Шаг 5. Установка приложения

Страница релизов: https://openm1ke.github.io/Secret-Tunnel/releases.html

- **macOS 15+**: файл `.dmg`, перенести Secret Tunnel в «Программы». Если macOS не даёт открыть: Системные настройки → Конфиденциальность и безопасность → «Всё равно открыть».
- **Windows 10/11**: `…-windows-x64-setup.exe`. Предупреждение SmartScreen («неизвестный издатель») — «Подробнее» → «Выполнить в любом случае». Проверить файл: `Get-FileHash .\SecretTunnel-*-setup.exe -Algorithm SHA256` и сравнить с `SHA256SUMS.txt`.
- **Android 8+**: `…-android.apk`, разрешить установку из этого источника.

## Шаг 6. Первое подключение (компьютер)

1. Вкладка «Серверы» → «Добавить». Поля: «Название», «Адрес сервера», «Порт SSH», «Пользователь», «Приватный ключ SSH» (выбрать файл `~/.ssh/secret-tunnel`, без `.pub`). «ID» заполняется из названия. В 0.3.22 и раньше русское название оставляет ID пустым, и «Сохранить» неактивна; тогда назовите сервер латиницей.
2. Для цепочки: сначала добавить промежуточный сервер отдельным профилем, затем в профиле сервера выхода выбрать его в поле «Подключаться через». В списке появится «RU → France».
3. «Сохранить», затем «Проверить SSH и агент». Ошибки — в таблице ниже.
4. Вкладка «Подключение»: выбрать сервер и «Локальный прокси для приложений» (по умолчанию `127.0.0.1:1080`), нажать «Подключить». Лента вверху покажет маршрут и страну выхода.

Только браузер, без выбора программ: указать в браузере или расширении (например, FoxyProxy) SOCKS5 `127.0.0.1:1080` и включить «проксировать DNS через SOCKS».

## Шаг 7. Выбор программ (компьютер)

**macOS:** нужен ProxyBridge 4.1.2 для macOS: https://github.com/InterceptSuite/ProxyBridge/releases/tag/v4.1.2_MacOS — установить в «Программы», окно самого ProxyBridge закрыть.

**Windows:** компонент перехвата уже в установщике; запускать Secret Tunnel от имени администратора.

Затем:

1. Подключить туннель (шаг 6).
2. Вкладка «Приложения»: отметить программы переключателями, «Включить перехват».
3. macOS при первом включении попросит разрешить расширение: Системные настройки → Основные → Объекты входа и расширения → ProxyBridge → сетевое расширение.
4. Перезапустить отмеченные программы: перехват действует на новые соединения.

Программы, которые запускает выбранное приложение (у ChatGPT — `codex`, `node`), на macOS подхватываются сами за секунду.

## Шаг 8. Android

Вкладки внизу: «Главная», «Приложения», «Скорость», «Статистика», «Ещё». Серверы, прокси, настройки и журнал — во «Ещё».

1. «Ещё» → «Серверы» → добавить сервер, «Импортировать SSH-ключ» — выбрать файл приватного ключа. Перенесите его на телефон по кабелю или AirDrop, не через мессенджеры, и удалите копию после импорта. Кнопка «Создать отдельный ключ телефона» заведёт новый ключ только для телефона и сама добавит его на сервер.
2. Цепочка: в сервере выхода поле «Подключаться через» → промежуточный сервер.
3. «Ещё» → «Прокси» → профиль → «SSH-сервер»: выбрать сервер выхода.
4. «Приложения» → отметить нужные.
5. «Главная» → «Подключить», сверить отпечаток сервера, разрешить VPN.

Одновременно в Android работает только один VPN — другой нужно выключить.

Обновления Android: «Ещё» → «О программе» → «Проверить». Если есть новая версия, скачайте обновление и подтвердите установку в Android. В разделе «Агент на сервере» можно проверить и установить версию агента для Linux x86_64, которая соответствует установленному приложению.

## Шаг 9. Проверка

- Вкладка «Скорость»: «Быстрый» через туннель и «Без туннеля» — сравнить скорость и страну выхода.
- Журнал внизу окна, фильтр «Соединения»: строки вида «туннель · Telegram → api.telegram.org :443».
- Вкладка «Статистика» покажет трафик по программам после использования.

## Частые ошибки

| Что видно | Что делать |
| --- | --- |
| `Permission denied (publickey)` | Ключ не добавлен на сервер или выбран `.pub`. Повторить шаг 2, в приложении указать файл без `.pub`. |
| Ключ хоста отклонён | Шаг 4: сверить отпечаток, обновить `known_hosts`. |
| `AGENT_MISSING` | Агент не установлен на сервере выхода — шаг 3. |
| `AGENT_NOT_EXECUTABLE` | Файл агента без права запуска: переустановить через `install-server-agent.sh`. |
| «Сохранить» неактивна | Пустой ID: назвать сервер латиницей (0.3.22 и раньше). |
| `Connection refused` на порту 2222 | SSH не перезапущен или порт закрыт фаерволом хостера: в старом окне `ss -tlnp \| grep 2222`. |
| `AGENT_INCOMPATIBLE` | Старый агент — установить агент того же релиза, что приложение. |
| Программа идёт мимо туннеля | Перезапустить её; проверить предупреждения на вкладке «Приложения». |
| macOS: перехват не включается | Разрешить расширение ProxyBridge (шаг 7, п. 3), закрыть окно ProxyBridge. |
| Windows: перехват недоступен | Запустить Secret Tunnel от имени администратора. |
| Включён другой VPN (Clash и т. п.) | На macOS оставить «SSH мимо других VPN» в настройках. |

Если не помогло — пусть пользователь скопирует журнал (с выключенным показом IP, кнопка с глазом) и создаст Issue: https://github.com/openm1ke/Secret-Tunnel/issues

## Где что лежит

| Что | macOS | Windows |
| --- | --- | --- |
| Ключ (по этой инструкции) | `~/.ssh/secret-tunnel` | `%USERPROFILE%\.ssh\secret-tunnel` |
| Известные серверы | `~/.ssh/known_hosts` | `%USERPROFILE%\.ssh\known_hosts` |
| Настройки приложения | `~/.config/secret-tunnel/config.json` | `%APPDATA%\secret-tunnel\config.json` |
| Статистика и замеры | там же, `sessions.json`, `speedtests.json` | там же |
| Агент на сервере | `~/.local/bin/secret-tunnel-agent` | — |

Приложение не копирует ключи: в настройках хранится только путь к файлу.
