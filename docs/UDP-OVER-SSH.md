# TCP и UDP через одно SSH-соединение

## Принятое решение

На участке Windows → зарубежный сервер используется одно SSH TCP-соединение. TCP приложения передаётся через direct-tcpip; UDP — в бинарных кадрах через session/exec канал того же SSH handle. Удалённая команда `secret-tunnel-agent` читает stdin, создаёт UDP-сокеты и возвращает ответы через stdout. Публичный порт агента не нужен; SSH-учётная запись должна иметь право запускать команду. Обычный sshd остаётся точкой входа.

React/Tauri сохраняются. Rust backend отвечает за SSH, SOCKS, статистику и ошибки. Серверный агент — отдельный Rust crate без зависимости от Tauri. На сервере агент работает от непривилегированного пользователя. Выходящие UDP-сокеты сервера к адресатам необходимы и не нарушают ограничение одного клиентского SSH-соединения.

## Этапы

1. Собрать исходный Windows-клиент после установки Node/npm, Rust MSVC, C++ Build Tools и Windows SDK. Сохранить аудит исходного commit отдельно от результатов последующих исправлений.
2. Реализовать ограниченный бинарный протокол, агент и тесты UDP echo без SSH.
3. Добавить SOCKS5 UDP ASSOCIATE во встроенный движок. Один exec-канал агента на ассоциацию, все каналы внутри существующего SSH-соединения. Это упрощает изоляцию и очистку, не создавая новых сетевых SSH-соединений.
4. Проверить реальный Linux sshd: TCP и UDP одновременно, ошибку запуска агента, потерю связи, закрытие SOCKS control TCP, IPv4/IPv6 и DNS.
5. Отдельно реализовать выбор приложений Windows через готовый сетевой компонент/WFP. Наличие SOCKS UDP не перехватывает Discord автоматически.

## Протокол v1

Двунаправленный поток начинается с magic `STUDP001` от агента. Каждый последующий кадр: u16 big-endian длина тела; тело — SOCKS5 UDP packet (`RSV=0`, `FRAG=0`, ATYP, адрес, порт, payload). Максимум тела 65507 байт; фрагментация SOCKS не поддерживается. Для запроса адрес — получатель, для ответа — отправитель. Нулевой UDP payload допустим. Неверные/слишком большие кадры завершают канал.

Агент поддерживает до 256 адресатов на ассоциацию. Для каждого адресата используется connected UDP socket: ответы принимаются только от этого адресата. Простой первый вариант при достижении лимита закрывает канал; последующая версия должна добавить явные сообщения ошибок и idle eviction. DNS разрешается на сервере. stdout содержит только протокол, stderr — диагностику. Отсутствие magic/таймаут означает несовместимый или не установленный агент.

Ассоциация принадлежит одному локальному SOCKS TCP-клиенту; UDP принимается только с его IP, первый допустимый source port фиксируется (ненулевой порт в запросе имеет приоритет). Закрытие control TCP удаляет ассоциацию. Входной SOCKS доступен только через loopback в первом прототипе. Счётчики учитывают полезную UDP нагрузку, а не SSH overhead.

## Ограничения и защита

SSH/TCP вызывает head-of-line blocking: потеря сегмента задерживает голос вместе с остальными каналами. Ограничить кадры, потоки, очереди и время ожидания; при обрыве не воспроизводить накопленный голос. Проверить качество при одновременной загрузке и искусственных потерях. Нельзя гарантировать качество Discord без таких измерений.

Агент имеет сетевые права SSH-пользователя, включая доступ к внутренним адресам сервера. Не публиковать агент как неаутентифицированный сервис; для выделенных аккаунтов применять egress firewall. Не писать payload, ключи и токены в логи. Обязательны проверка SSH host key, корректное завершение задач и отсутствие fallback наружу при ошибке UDP.

## Проверки приёмки

- Границы датаграмм, пустые payload, IPv4/IPv6/domain и отказ FRAG.
- Параллельный UDP echo для нескольких адресатов, большие пакеты, закрытие stdin.
- SOCKS UDP ASSOCIATE и двусторонний echo через Linux sshd; на клиенте ровно одно внешнее TCP-соединение к SSH и ноль прямых UDP к адресату.
- Не установленный агент, неверный magic, DNS failure, лимит потоков и обрыв SSH дают диагностируемый отказ.
- Discord: чат/голос/видео, переподключение, сон, смена сети; затем отдельная проверка перехвата выбранного приложения.

## Сборка агента

На Linux-сервере из корня репозитория: `cargo build --release --manifest-path udp-agent/Cargo.toml`. Установить `udp-agent/target/release/secret-tunnel-agent` в `~/.local/bin/secret-tunnel-agent` с правами 700. Клиент использует `exec "$HOME/.local/bin/secret-tunnel-agent"`, поэтому изменение PATH не требуется. Автоматического копирования и изменения сервера клиент не выполняет.
