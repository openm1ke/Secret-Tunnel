# TCP и UDP через один SSH-канал: транспорт v3

Windows, macOS и Android используют общий `tunnel-core` и crate `stream-mux`. Встроенный движок открывает одно аутентифицированное SSH TCP-соединение. Он завершает короткий запрос возможностей агента и затем открывает один exec-канал данных.

```text
Приложения → локальный SOCKS / Android TUN → STMUX003 → SSH → агент → адресаты
```

Агент запускается командой `exec "$HOME/.local/bin/secret-tunnel-agent" --stdio-v3`. TCP и UDP передаются внутри одного канала с отдельными идентификаторами. Клиент 0.3.0 требует capabilities schema 1 и STMUX003. System OpenSSH `ssh -D` остаётся отдельным TCP-only движком. [Диагностика агента](AGENT-PREFLIGHT-2026-11-09.md).

## Потоки, очереди и память

- Согласование: magic `STMUX003`, затем три u32 big-endian — максимум потоков, окно приёма в байтах и число пакетов в окне. Обе стороны используют меньший предел потоков.
- Кадр: u16 длина тела, u8 тип, u32 flow ID, payload. Типы: OpenTcp, OpenUdp, Accepted, Rejected, Data, Eof, Close, Credit, Abort, Stats. ID 0 зарезервирован для статистики; остальные ID монотонны, с разной чётностью сторон и без повторного использования в сеансе.
- У каждого потока окно 64 КиБ / 64 пакета. Credit возвращается после передачи данных локальному потребителю, а не сразу после получения SSH-пакета. Заблокированное приложение не останавливает общий читатель и соседние потоки.
- TCP разбивается на куски до 16 КиБ, использует backpressure и сохраняет half-close. Data, Eof и штатный Close идут в одной очереди; аварийный Abort передаётся отдельно. TCP-данные при перегрузке не отбрасываются.
- UDP сохраняет границы датаграмм и отдельный серверный source socket каждой ассоциации. Допустимы IPv4, IPv6 и domain; SOCKS FRAG отвергается. Общий пул из 16 временных буферов заменяет большой буфер на каждую простаивающую ассоциацию.
- Общая отправная очередь ограничена 8 МиБ и 4096 кадрами. UDP, которому не хватает credit/места, отбрасывается с явным счётчиком; неограниченной очереди нет. Control-очередь тоже ограничена. Writer объединяет до 32 готовых кадров примерно в 64 КиБ без ожидания накопления.
- При 2048 потоках верхняя граница полезных данных очередей приёма — 128 МиБ. Буферы выделяются по потребности. Это предел очередей протокола, а не всей памяти процесса: отдельно существуют TUN, сокеты ОС, SSH, runtime и служебные структуры.
- Клиент и агент согласуют предел с учётом доступных файловых дескрипторов; агент поддерживает до 2048 потоков. При необходимости каждый повышает только свой soft RLIMIT_NOFILE до min(hard, 8192). Один TCP-поток занимает один серверный сокет; UDP-ассоциация — до двух (IPv4/IPv6). Новое соединение сверх лимита получает отказ, не вытесняя действующие.
- UDP допускает до 256 адресатов на ассоциацию. Ответы принимаются только от запрошенных IP/port; простаивающие адресаты очищаются через 120 секунд. При заполнении списка активные адресаты не вытесняются молча. DNS/connect/send ошибки и перегрузка видны в диагностике.

Stats передаёт клиенту агрегированные счётчики сервера. Payload, ключи и токены не журналируются. Переподключение создаёт новый транспорт; недоставленные голосовые пакеты не воспроизводятся.

## Проверки

```bash
cargo test --manifest-path stream-mux/Cargo.toml --locked
cargo test --manifest-path udp-agent/Cargo.toml --locked
cargo test --manifest-path tunnel-core/Cargo.toml --locked
```

Тесты проверяют 1024 изолированных потока, приостановленного потребителя, byte/slot credit, переполнение, разбитый byte stream, half-close, статистику и завершение. Интеграционные тесты агента запускают настоящий дочерний процесс: 2048 одновременно открытых TCP-соединений, отказ 2049-му, точные payload и совместные UDP/TCP. На Linux дополнительно проверяют RSS агента <256 МиБ при удержании соединений.

`scripts/check-multiplex-load.py` проверяет локальный SOCKS через контролируемые TCP/UDP echo-серверы на loopback удалённого узла: 2048 TCP, 64 UDP, 8 МиБ, half-close и медленного потребителя. Тест не предназначен для нагрузки на чужой публичный сервис. Результаты реального SSH и Android: [проверка v3](TRANSPORT-V3-2026-11-09.md).

## Практический предел

Один SSH/TCP транспорт всё ещё имеет сетевой head-of-line blocking: потеря внешнего TCP-сегмента задерживает все потоки. Credit устраняет блокировку из-за медленного приложения, но не отменяет свойства TCP, доступность CDN, ограничения сервера или потери внешнего UDP. Успех нагрузочных тестов не гарантирует загрузку любого Instagram-видео или качество Discord в любой мобильной сети.
