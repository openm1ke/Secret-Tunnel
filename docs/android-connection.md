# Android: подключение и доверие SSH

## Сценарий

1. Указать адрес, порт и пользователя SSH.
2. Импортировать уже разрешённый ключ OpenSSH/PEM без пароля.
3. Нажать «Проверить сервер и его ключ»: клиент выполняет SSH key exchange без аутентификации, получает SHA256 и отклоняет эту пробную сессию. Пользователь сверяет отпечаток по доверенному каналу и подтверждает его.
4. При желании нажать «Создать отдельный ключ этого телефона». Генерируется Ed25519; через существующий ключ добавляется публичная часть в ~/.ssh/authorized_keys этого пользователя. Затем выполняется новый SSH-вход с ключом телефона. Только после успешной проверки приложение заменяет сохранённый ключ.
5. Выбрать приложения и подключиться. После проверки сервера Android запрашивает разрешение VPN. TCP и UDP выбранных приложений идут через SSH.

Проверка сервера и разрешение клиенту входа — разные операции. Без существующего ключа или другого уже разрешённого доступа автоматически получить права на сервере нельзя. Парольная аутентификация пока не реализована.

## Хранение и ошибки

Отпечаток больше не вводится вручную. Старые значения, похожие на файловый путь, сбрасываются при сохранении настроек. Смена адреса или порта сбрасывает доверие. Изменившийся ключ сервера требует отдельного подтверждения; автоматически он не принимается.

Приватный ключ хранится в AES-GCM с Android Keystore; временные файлы MODE_PRIVATE удаляются после операции и при следующем запуске приложения. Ключи и пароль в APK не встраиваются. authorized_keys дополняется идемпотентно, существующие записи и службы SSH/Xray/wstunnel не меняются. Неудачная регистрация не заменяет прежний сохранённый ключ; добавленная публичная запись может остаться на сервере, если проверка оборвалась.

## Проверки

Сборка: scripts/build-android.ps1; выполняет native ARM64/x86_64, Kotlin, lint, unit tasks, ELF/ZIP 16KB alignment и APK signature checks.

Инструментальные тесты: android/app/src/androidTest/java/dev/secrettunnel/android/ConnectionTest.kt. Проверяют получение ключа без credentials, неверный порт, генерацию и зашифрованное хранение ключа. Дополнительная интеграционная проверка регистрации включается только при наличии files/bootstrap-test.key в приватном каталоге отладочного приложения: проверяет отказ неверному pin, регистрацию, повторную регистрацию и реальный вход новым ключом. Тестовые публичные ключи после проверки нужно отозвать; никаких credentials в репозитории нет.

Для сетевых инструментальных тестов передайте в AndroidJUnitRunner аргументы sshHost, sshPort, sshUser и sshFingerprint. На устройстве используется отдельный временный bootstrap-test.key; постоянные адреса и учётные данные в тестовый исходник и APK не встраиваются.
