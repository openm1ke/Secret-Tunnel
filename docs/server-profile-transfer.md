# Защищённый перенос серверов

Доступно начиная с версии 0.3.33. Реализация — в ветке `codex/encrypted-server-transfer`.

## Как пользоваться

На отправляющем устройстве: **Серверы → Поделиться → Подготовить перенос**.
Можно передать один сервер вместе с промежуточными узлами или все настроенные
серверы. Получатель выбирает **Серверы → Импортировать**, сканирует QR-код,
вставляет ссылку или открывает файл `.stprofile`, затем вводит код переноса.
До подтверждения показываются только параметры серверов. Существующие профили
не заменяются. После импорта выберите сервер и проверьте соединение.

На Android TV используется системный выбор документов: файл можно открыть
с флешки, если прошивка телевизора предоставляет её через этот интерфейс.
При отсутствии файлового провайдера на конкретной прошивке можно вставить ссылку.
Камера для TV не требуется. Интернет для переноса не нужен.

## Протокол STP1

Все три способа используют один формат:
`secrettunnel://import#stp1.<base64url>`.
Base64url служит только для записи двоичных данных в ссылке.

Конверт: `STP\x01 | salt[16] | nonce[12] | AES-256-GCM ciphertext + tag[16]`.
Ключ шифрования выводится Argon2id v19: 19456 КиБ памяти, 2 прохода,
1 поток, выход 32 байта. AAD — четырёхбайтовая сигнатура формата.
Перед шифрованием JSON сжимается zlib. При расшифровке сначала проверяется
подлинность, затем выполняется распаковка с жёстким пределом размера.
Параметры KDF фиксированы версией формата, входные данные не могут их увеличить.

Код создаётся из 20 равномерных случайных символов алфавита из 32 знаков
(100 бит). Это отдельный секрет, он не входит в ссылку, QR или файл.
Регистр, пробелы и дефисы при вводе не имеют значения. Соль и nonce
случайны для каждого экспорта. Код не сохраняется приложением, после закрытия
окна старый экспорт без сохранённого кода не восстановить.

Получатель, владеющий файлом и кодом, получает доступ по вложенному SSH-ключу.
Это копия ключа, а не отдельное разрешение для нового устройства. Удаление
его публичной части с сервера отзовёт все такие копии. Экспорт не имеет срока
действия и не становится недействительным после первого импорта. Передавайте
код отдельно от зашифрованных данных. Для независимого отзыва доступа в будущем
нужен отдельный ключ для каждого устройства.

## Состав и ограничения

- Переносятся адрес, порт, SSH-пользователь, название, приватный ключ,
  подтверждённый отпечаток хоста и цепочка SSH.
- Не переносятся выбор приложений, защита при обрыве, настройки перехвата,
  настройки производительности, пароли от сервера и параметры интерфейса.
- До 32 серверов, до трёх промежуточных узлов в маршруте, ключ до 16 КиБ.
  Ключи с парольной фразой пока не поддерживаются.
- Вход до 1 МиБ, распакованный документ до 768 КиБ. Большие документы
  передаются файлом или ссылкой; QR ограничен 2300 байтами ссылки, ECC M.
- Импорт создаёт новые случайные идентификаторы и отдельные локальные файлы
  ключей. Ошибка проверки не меняет настройки. Android сохраняет ключи
  зашифрованными ключом из Keystore, iOS использует защищённые файлы без бэкапа,
  desktop — приватный каталог и права 0600 на Unix.
- Импортированные отпечатки обязательны при SSH-подключении; desktop выбирает
  встроенный движок для профилей с отпечатком, поскольку системный OpenSSH
  не использует это поле профиля.

## Проверка

Общий Rust-код проверяет повторный экспорт со случайным шифротекстом,
неверный код, подмену данных, повреждённые маршруты, ограничение распаковки
и перенос больших документов без QR. Desktop integration test использует
изолированный `SECRET_TUNNEL_TEST_CONFIG_DIR`, не боевые настройки.

На macOS через настоящий интерфейс проверены создание QR, сохранение
зашифрованного файла, предварительный просмотр и подтверждённый импорт.
В эмуляторе Android 14 проверены mobile и TV варианты: импорт документа через content URI,
ошибка неверного кода без изменения настроек, подтверждение, сохранение ключей
в Keystore, маршрута и существующих профилей. TV прогон выполняется без сети.
Android ZXing и iOS CoreImage читают QR, созданный desktop; iOS Simulator
проверяет сохранность ключей, отпечатков и цепочки после импорта.
На Android вручную проверены открытие системного выбора файлов, запуск
сканера, запрос разрешения камеры и возврат без импорта при отмене.
Фикстуры используют только новые тестовые ключи и адреса из 203.0.113.0/24.

Считывание настоящей камерой с экрана и импорт с физической флешки на телевизоре
ещё требуют проверки на устройствах. Компиляция Windows проверяется CI;
локальная проверка desktop выполняется на macOS.
